Section 01

What Is an Operating System

Before we define it — take a guess: a car, an airplane, a printer, a washing machine, a toaster, a compiler — which of these "has" an operating system? Almost all of them, just at very different levels of complexity. Trước khi định nghĩa — đoán thử xem: xe hơi, máy bay, máy in, máy giặt, lò nướng bánh, trình biên dịch — cái nào "có" một hệ điều hành? Gần như tất cả, chỉ khác nhau ở độ phức tạp mà thôi.

Strip away everything else and an OS is just a program with an unusual job: it sits between every application you run and the physical machine underneath, and it never really stops running.

Bỏ hết mọi thứ phụ đi, OS chỉ là một chương trình có nhiệm vụ đặc biệt: nó đứng giữa mọi ứng dụng bạn chạy và phần cứng thật bên dưới, và gần như không bao giờ ngừng chạy.
User / Application

→
Operating System
translates & guards
→
Hardware
CPU, disk, memory

Two goals pull the OS in different directions at once. One is convenience — a person shouldn't need to know which cylinder of the disk a file lives on to get work done. The other is efficiency — the actual silicon, memory, and I/O bandwidth need to be squeezed for as much useful work as possible, because none of it is free.

Hai mục tiêu này luôn kéo OS về hai hướng khác nhau. Convenience là sự tiện lợi — người dùng không cần biết file nằm ở cylinder nào trên đĩa. Efficiency là hiệu quả — phải tận dụng tối đa CPU, bộ nhớ, băng thông I/O vì không có gì miễn phí.
⚖️
Convenience ↔ Efficiencygần như mọi quyết định thiết kế OS là sự đánh đổi giữa hai đầu cân này.

The narrowest possible definition of "operating system" is the kernel: the one piece of code that's resident and running at all times. Everything shipped alongside it is a system program if it comes bundled with the OS, or an application program if it doesn't.

Định nghĩa hẹp nhất của "hệ điều hành" chính là kernel — phần lõi luôn chạy thường trực. Mọi thứ đi kèm nó là "system program" nếu được đóng gói sẵn cùng OS, hoặc "application program" nếu không.
🧅
Kernel ⊂ System programs ⊂ Applicationsgiống các lớp củ hành — kernel nằm trong cùng, luôn chạy; ngoài cùng là app do bạn tự cài.

Modern general-purpose and mobile OSes also bundle middleware: shared software frameworks that sit above the kernel and give applications ready-made services — databases, graphics rendering, media playback — so every app doesn't have to reinvent them from scratch.

Các OS tổng quát và di động ngày nay còn đóng gói kèm "middleware" — những framework phần mềm dùng chung, nằm trên kernel, cung cấp sẵn dịch vụ cho ứng dụng (cơ sở dữ liệu, xử lý đồ họa, phát media) để mỗi app không phải tự viết lại từ đầu.
🧰
Middleware = hộp đồ nghề dùng chungapp nào cần database/đồ họa/media cứ lấy ra dùng, không cần tự chế lại.

Not every device needs the same kind of OS. A shared mainframe needs to referee many users fairly; a smartphone needs to protect battery life; an embedded controller may run with no user interface at all.

Không phải thiết bị nào cũng cần cùng 1 kiểu OS. Máy chủ dùng chung phải phân xử công bằng cho nhiều người; điện thoại phải giữ pin; bộ điều khiển nhúng có thể chạy mà chẳng cần giao diện người dùng nào cả.
Shared / mainframe

Nhiều người dùng cùng lúc — phân bổ tài nguyên công bằng.

Dedicated / workstation

Tài nguyên riêng, nhưng vẫn hay gọi tới server.

Mobile devices

Ít tài nguyên hơn — tối ưu cho pin, cảm ứng.

Embedded computers

Gần như không có giao diện, tự chạy 1 mình.

Mẹo thiNếu đề hỏi "operating system is..." dạng điền khuyết — câu trả lời an toàn nhất luôn là: chương trình trung gian giữa user và hardware, mục tiêu là convenience + efficient resource use.

Section 02

System Structure, Architecture & Interrupts

Zoom out and a computer is only four layers talking to each other in strict order — nothing skips a level.

Nhìn tổng quát, máy tính chỉ có 4 lớp nói chuyện với nhau theo đúng thứ tự — không lớp nào được nhảy cóc.
Users — people, other machines, other software
↕
Application programs — compilers, browsers, games
↕
Operating system — allocates & coordinates hardware
↕
Hardware — CPU, memory, I/O devices

Every part of a machine — CPU, disk, keyboard, graphics card — plugs into a shared system bus that provides the only path to memory. Each device sits behind its own controller; a device driver installed inside the OS is what actually talks to that controller.

Mọi bộ phận của máy — CPU, ổ đĩa, bàn phím, card đồ họa — đều cắm vào 1 hệ thống bus chung, đường duy nhất tới bộ nhớ. Mỗi thiết bị đứng sau 1 bộ điều khiển riêng; "device driver" cài trong OS mới thực sự nói chuyện với bộ điều khiển đó.

Hardware doesn't wait around for the CPU to ask "is anything ready yet?" Instead, every device controller can raise an interrupt, looked up through an interrupt vector. Before jumping, hardware preserves the CPU's registers and program counter, so execution resumes exactly where it left off.

Phần cứng không ngồi chờ CPU hỏi "có gì sẵn sàng chưa" — thay vào đó, mỗi bộ điều khiển thiết bị có thể phát ra 1 "interrupt", được tra cứu qua "interrupt vector". Trước khi nhảy sang xử lý, phần cứng lưu lại thanh ghi và program counter của CPU, để sau đó chạy tiếp đúng chỗ đã dừng.

When I/O traffic is light, interrupts are efficient; once the rate climbs high enough, some drivers switch to polling instead — repeatedly checking device status directly.

Khi lưu lượng I/O thấp, dùng interrupt là hiệu quả; nhưng khi tốc độ tăng quá cao, 1 số driver chuyển sang "polling" — tự kiểm tra trạng thái thiết bị liên tục thay vì chờ interrupt.
🔁
Interrupt vs Pollingít việc → interrupt (đỡ tốn công); nhiều việc dồn dập → polling (hỏi liên tục lại rẻ hơn).

Interrupts don't only come from hardware. A trap (or exception) is a software-generated interrupt — an illegal instruction, or a deliberate system call, the only sanctioned doorway into the kernel.

Interrupt không chỉ đến từ phần cứng. "Trap" (hay exception) là interrupt do phần mềm tạo ra — có thể là lỗi (như chia cho 0), hoặc 1 "system call" cố ý gọi tới, và đây là cửa duy nhất được phép để vào kernel.
🚪
System call = cửa chính thứcduy nhất để chương trình người dùng "gõ cửa" xin kernel làm việc gì đó.

For devices that move a lot of data, interrupting the CPU once per byte would be absurd. DMA lets the controller copy an entire block straight into main memory on its own, interrupting the CPU only once the whole block is done.

Với thiết bị truyền nhiều dữ liệu, cứ mỗi byte lại ngắt CPU 1 lần thì quá vô lý. "DMA" cho phép bộ điều khiển tự copy cả 1 khối dữ liệu thẳng vào bộ nhớ, chỉ ngắt CPU đúng 1 lần khi xong cả khối.
📦
DMA1 lần ngắt cho cả khối dữ liệu, thay vì ngắt liên tục từng byte một.

Architecture: one CPU isn't the whole story anymore

Most machines today carry more than one processing core. Grouping cores together — multiprocessing — buys higher throughput and graceful degradation if one core fails.

Hầu hết máy ngày nay có nhiều hơn 1 lõi xử lý. Gộp nhiều lõi lại — "multiprocessing" — giúp tăng thông lượng, và nếu 1 lõi hỏng thì máy vẫn chạy được (chỉ chậm hơn) thay vì chết hẳn.
CPU 0
registers · cache
CPU 1
registers · cache
shared main memory

In asymmetric multiprocessing, one processor is boss and hands specific tasks to the rest. In symmetric multiprocessing (SMP) — the common case today — every core is an equal.

Trong "asymmetric multiprocessing", 1 CPU làm sếp, giao việc cho các CPU còn lại. Trong "symmetric multiprocessing (SMP)" — kiểu phổ biến hiện nay — mọi lõi đều bình đẳng như nhau.
👔
Asymmetric = có sếp · Symmetric = bình đẳngSMP là kiểu chip đa lõi trên laptop/điện thoại bạn đang dùng.

Multiple cores can be packaged three ways: several cores on one chip (multicore), several separate chips inside one socket (multi-chip), or a whole chassis housing multiple independent systems side by side. Multicore designs usually give each core its own small L1 cache, then share a larger L2 cache between them.

Nhiều lõi có thể đóng gói theo 3 kiểu: nhiều lõi trên 1 chip ("multicore"), nhiều chip riêng trong cùng 1 socket ("multi-chip"), hoặc cả 1 khung máy chứa nhiều hệ thống độc lập cạnh nhau. Thiết kế multicore thường cho mỗi lõi 1 cache L1 nhỏ riêng, rồi dùng chung 1 cache L2 lớn hơn.
🧩
Multi-chip ≠ Multicoremulticore = nhiều lõi trong 1 chip; multi-chip = nhiều chip riêng trong 1 socket.

As core counts grow, memory access stops being equally fast for everyone: in a Non-Uniform Memory Access (NUMA) design, each CPU has its own local memory bank reached quickly, and reaches other CPUs' memory more slowly.

Khi số lõi tăng lên, tốc độ truy cập bộ nhớ không còn đều nhau nữa: trong thiết kế "NUMA", mỗi CPU có 1 vùng nhớ riêng truy cập nhanh, còn truy cập vùng nhớ của CPU khác thì chậm hơn.

+ memory 0

CPU 2
+ memory 2
CPU 3
+ memory 3

Scale further and you leave a single box entirely: clustered systems wire separate machines together, sharing storage through a SAN. Asymmetric clustering keeps one machine on hot standby; symmetric clustering runs on every node at once. Clusters built purely for raw computation are called High-Performance Computing (HPC) — their applications must be explicitly written to be parallelized to take advantage of every node. A Distributed Lock Manager (DLM) stops two nodes touching the same resource together.

Mở rộng hơn nữa thì ra khỏi 1 chiếc máy hẳn: "clustered systems" nối nhiều máy riêng biệt lại, chia sẻ ổ lưu trữ qua "SAN". "Asymmetric clustering" giữ 1 máy dự phòng chờ sẵn; "symmetric clustering" cho mọi máy cùng chạy. Cluster dựng riêng để tính toán nặng gọi là "High-Performance Computing (HPC)" — ứng dụng phải được viết riêng để chia nhỏ (parallelize) mới tận dụng hết các node. "DLM" ngăn 2 máy đụng vào cùng 1 tài nguyên cùng lúc.
🔗
Clusternhiều máy vật lý riêng biệt, nối mạng, chia sẻ storage — khác hẳn multiprocessor (vẫn là 1 máy).
Mẹo thiNUMA ≠ cluster: NUMA vẫn là 1 máy vật lý, nhiều CPU truy cập không đều vào các vùng nhớ. Cluster là nhiều máy riêng biệt, nối qua mạng, chia sẻ storage.

Section 03

OS Operations & Resource Management

From the instant a machine powers on, a fixed sequence kicks in before any user program ever runs.

Ngay từ lúc bật nguồn, 1 trình tự cố định bắt đầu chạy trước khi bất kỳ chương trình người dùng nào được chạy.
Bootstrap
Firmware in ROM initializes the system
Kernel loads
Control passes to the OS kernel
Daemons start
Background services outside the kernel
Interrupt-driven
Kernel waits, reacts to events

Once running, the kernel spends its life reacting: a hardware interrupt, or a software one — an illegal instruction, a system call, or messier problems like an infinite loop. A timer forces control back to the kernel before things freeze.

Một khi đã chạy, kernel sống bằng cách phản ứng: interrupt phần cứng, hoặc phần mềm — lệnh sai, system call, hay rắc rối hơn như 1 vòng lặp vô hạn. "Timer" ép trả quyền điều khiển về kernel trước khi máy bị treo.

What exactly is a "process"?

A program sitting on disk is a passive entity — just bytes. The instant it starts running, it becomes a process: an active entity with its own program counter and resources.

Một "chương trình" nằm trên đĩa chỉ là dữ liệu thụ động — toàn byte. Ngay khi nó bắt đầu chạy, nó trở thành "process" — 1 thực thể chủ động, có program counter và tài nguyên riêng của nó.
Program

Passive. A file on disk. No state, no progress.

Process

Active. Has a program counter, owns resources, makes progress.

A classic single-threaded process runs one instruction at a time; a multi-threaded process keeps one program counter per thread, letting several lines of execution share the same process's resources at once.

Process đơn luồng chạy từng lệnh một; "multi-threaded process" giữ 1 program counter riêng cho mỗi luồng, cho phép nhiều dòng chạy chia sẻ chung tài nguyên của cùng 1 process.
🧵
Single-thread vs Multi-thread1 luồng = 1 program counter; nhiều luồng = nhiều program counter cùng chung tài nguyên process.

Multiprogramming → timesharing

A single user rarely keeps the CPU and every I/O device busy at once. Multiprogramming keeps several jobs in memory so the CPU always has something to execute.

Một người dùng hiếm khi khiến CPU và mọi thiết bị I/O bận rộn cùng lúc. "Multiprogramming" giữ nhiều job trong bộ nhớ để CPU luôn có việc để làm.

Push that switching fast enough for real-time interaction and you get timesharing (multitasking), with a response-time target well under a second. When jobs don't fit in memory, swapping and virtual memory let them run anyway.

Đẩy tốc độ chuyển đổi đó lên đủ nhanh để tương tác thời gian thực, ta có "timesharing (multitasking)", với mục tiêu phản hồi dưới 1 giây. Khi job không vừa bộ nhớ, "swapping" và "virtual memory" vẫn cho nó chạy được.
Mẹo thiPhân biệt: Multiprogramming = có nhiều job trong memory để CPU không rảnh. Multitasking/Timesharing = multiprogramming + phản hồi đủ nhanh để user tương tác trực tiếp.

What the OS is actually keeping track of

The OS constantly manages four kinds of resources at once — processes, memory, files, and mass storage.

OS liên tục quản lý 4 loại tài nguyên cùng lúc — process, bộ nhớ, tệp tin, và bộ lưu trữ.
Process management

Create/delete processes, suspend/resume, synchronization, communication, deadlock handling.

Memory management

Track what's used and by whom, decide what moves in/out, allocate and free space.

Filesystem management

Create/delete files & directories, control access, map files onto secondary storage.

Mass-storage management

Mount/unmount, free-space tracking, disk scheduling, partitioning, protection.

The I/O subsystem hides the mess

The I/O subsystem leans on three tricks: buffering (holding data temporarily mid-transfer), caching, and spooling — letting one job's output overlap with another's input, like a print queue.

Hệ thống I/O dựa vào 3 mẹo: "buffering" (giữ tạm dữ liệu khi đang truyền), "caching", và "spooling" — cho phép output của job này chồng lấp với input của job khác, ví dụ như hàng đợi in.
Buffering

Vùng giữ tạm khi dữ liệu di chuyển giữa 2 tốc độ khác nhau.

Caching

Bản sao nhanh hơn, giữ lại vì có thể dùng lại sớm.

Spooling

Xếp hàng để 1 thiết bị chậm (như máy in) không chặn mọi người khác.

Section 04

Storage Hierarchy

Every tier of storage is a compromise: the faster it is, the smaller and pricier it gets per byte.

Mỗi tầng lưu trữ đều là 1 sự đánh đổi: càng nhanh thì càng nhỏ và càng đắt mỗi byte.
Registers< 1 KB · fastest
Cache (on/off-chip)< 16 MB
Main memory (DRAM)< 64 GB · volatile
Solid-state / NVM< 1 TB · non-volatile
Magnetic disk< 10 TB · slowest, cheapest
← faster / smaller / pricierslower / larger / cheaper →

Only the top of that ladder is something the CPU can touch directly; everything below is secondary storage, reached only through the OS.

Chỉ có đỉnh của bậc thang này là CPU chạm trực tiếp được; mọi thứ bên dưới là "secondary storage", chỉ tiếp cận được thông qua OS.
Mẹo thiTrật tự gần như luôn xuất hiện trong đề: registers → cache → main memory → NVM/SSD → HDD → optical → tape.

Đơn vị đo lường — nhắc lại cho chắc

The smallest unit is a bit. Eight bits make a byte — the smallest unit a computer typically moves directly. A word is a given architecture's native chunk of data.

Đơn vị nhỏ nhất là "bit". Gom 8 bit thành 1 "byte" — đơn vị nhỏ nhất máy tính thường thao tác trực tiếp. "Word" là đơn vị dữ liệu gốc của 1 kiến trúc máy cụ thể.

Khi có nhiều bản sao — ai mới là bản "thật"?

In a multitasking system, several copies of the same value can exist across this hierarchy — the OS has to guarantee whoever reads it gets the most recent write.

Trong hệ thống đa nhiệm, nhiều bản sao của cùng 1 giá trị có thể tồn tại xuyên suốt các tầng lưu trữ này — OS phải đảm bảo ai đọc giá trị đó cũng nhận được bản ghi mới nhất.

In a multiprocessor machine, this gets harder: each core keeps its own cache, so hardware must enforce cache coherency — making sure every core sees the latest value, not a stale copy sitting in a neighbor's cache. Push the same idea across a distributed system and it's harder still, since several physical machines can each hold their own copy of the same data at once.

Trong máy đa xử lý, việc này khó hơn: mỗi lõi giữ cache riêng, nên phần cứng phải đảm bảo "cache coherency" — mọi lõi đều thấy đúng giá trị mới nhất, không phải bản cũ còn sót trong cache của lõi khác. Đẩy ý tưởng này ra hệ phân tán thì còn khó hơn nữa, vì nhiều máy vật lý khác nhau có thể mỗi máy giữ 1 bản sao riêng của cùng 1 dữ liệu.
🔄

Section 05

Dual-Mode Operation & Security

The entire notion of "protection" in an OS collapses to one hardware bit. The CPU tracks a single mode bit: user or kernel. Privileged instructions won't run unless the mode bit already says kernel.

Toàn bộ khái niệm "bảo vệ" trong OS thu gọn lại thành 1 bit phần cứng. CPU theo dõi 1 "mode bit" duy nhất: user hoặc kernel. Lệnh "privileged" sẽ không chạy trừ khi mode bit đang là kernel.
User mode — mode bit = 1

Your process runs normally, then needs something only the kernel can do.

The trap hands control to a fixed entry point — the only way in.

Control returns exactly where the process left off.

A closely related safeguard is the timer: when its countdown hits zero, hardware forces an interrupt back to the kernel — the reason one infinite loop can't hold the whole system hostage.

Một cơ chế bảo vệ liên quan là "timer": khi đồng hồ đếm ngược về 0, phần cứng buộc phải ngắt trả về kernel — đây là lý do 1 vòng lặp vô hạn không thể giữ cả hệ thống làm con tin.

Two ways an I/O call can behave

Synchronous (blocking) I/O parks the process until the transfer's done. Asynchronous (non-blocking) I/O hands control straight back, and the OS tracks every device's state in a device-status table.

"Synchronous (blocking) I/O" bắt process đứng chờ tới khi truyền xong. "Asynchronous (non-blocking) I/O" trả quyền điều khiển ngay lập tức, và OS theo dõi trạng thái mọi thiết bị qua 1 "device-status table".
Blocking I/O

Đơn giản, nhưng CPU ngồi chờ không làm gì — chỉ 1 request tại 1 thời điểm.

Non-blocking I/O

Process tiếp tục chạy; OS theo dõi tiến độ qua bảng trạng thái.

Protection vs. security

Protection is any mechanism controlling which processes or users can touch which resources. Security is the broader defense against internal and external attacks.

"Protection" là bất kỳ cơ chế nào kiểm soát process hay user nào được đụng vào tài nguyên nào. "Security" là mục tiêu tổng thể rộng hơn — chống lại tấn công cả bên trong lẫn bên ngoài.

Systems distinguish users through a user identity (UID). A group identifier (GID) lets a whole set of users share permissions. Privilege escalation lets a process temporarily gain more rights.

Hệ thống phân biệt người dùng qua "UID". "GID" cho phép cả 1 nhóm người dùng chia sẻ quyền. "Privilege escalation" cho phép 1 process tạm thời có nhiều quyền hơn.

Section 06

Virtualization

Virtualization is the trick of making one physical machine convincingly pretend to be several separate ones, each running its own full guest operating system.

Virtualization là "chiêu" khiến 1 máy vật lý giả vờ là nhiều máy riêng biệt, mỗi máy chạy trọn vẹn 1 hệ điều hành khách (guest OS) của riêng nó.

Emulation is needed when the guest's CPU architecture doesn't match the host's — slow, since every instruction is translated. True virtualization assumes the same architecture, so it runs at near-native speed.

"Emulation" cần dùng khi kiến trúc CPU của máy khách khác với máy chủ — chậm, vì mọi lệnh đều phải dịch lại. "Virtualization" thật sự giả định cùng kiến trúc, nên chạy gần như tốc độ gốc.

The VMM hands out slices of real CPU, memory, and I/O to each guest while keeping them isolated. Some VMMs sit atop a host OS; others run directly on bare metal, the approach data centers favor.

"VMM" chia sẻ CPU, bộ nhớ, I/O thật cho từng máy khách trong khi vẫn cách ly chúng với nhau. Có VMM chạy trên 1 OS chủ; có loại chạy thẳng trên phần cứng trần, đây là cách các trung tâm dữ liệu hay dùng.

Section 07

Computing Environments

Distributed systems: it's all about the network

A distributed system is a collection of separate machines wired together by a network. That network can be a LAN inside one building, or stretched into a WAN across cities; MAN and PAN sit in between.

"Distributed system" là 1 tập hợp các máy riêng biệt được nối lại bằng mạng. Mạng đó có thể là "LAN" trong 1 tòa nhà, hoặc kéo dài thành "WAN" xuyên thành phố; "MAN" và "PAN" nằm ở giữa 2 quy mô đó.
📡
PAN → LAN → MAN → WANquy mô mạng tăng dần từ cá nhân (Bluetooth) tới cả thành phố/quốc gia.

A Network Operating System (NOS) doesn't merge machines into one computer, but gives them a shared way to exchange messages — so the boundary between "my machine" and "the network" mostly disappears.

"Network Operating System (NOS)" không biến nhiều máy thành 1 máy, nhưng cho chúng 1 cách chung để trao đổi thông điệp — nên ranh giới giữa "máy của tôi" và "mạng" gần như biến mất.
Mẹo thiThứ tự phạm vi mạng từ nhỏ đến lớn: PAN → LAN → MAN → WAN. NOS không biến nhiều máy thành 1 máy, chỉ tạo cảm giác như vậy.

Những nguyên lý OS giống nhau vẫn xuất hiện dưới nhiều hình dạng khác nhau, tùy vào thứ gì đang kết nối với thứ gì.

Mobile OSes earn their keep with extra hardware features — GPS, gyroscope — that unlock entirely new app categories like Augmented Reality (AR), and they connect over IEEE 802.11 wireless or cellular data. Apple iOS and Google Android lead this space.

A kernel leans on the same building blocks any program does. A singly linked list chains objects in one direction; a doubly linked list adds a pointer back to the previous node; a circular linked list loops the last node back to the first.

Binary search trees keep things ordered for O(n) lookups worst case — or O(log n) once balanced. Hash maps trade a little memory for near-constant-time lookup by key.

"Binary search trees" giữ dữ liệu có thứ tự, tra cứu O(n) trong tình huống xấu nhất — hoặc O(log n) khi cây đã cân bằng. "Hash map" đổi 1 chút bộ nhớ lấy tốc độ tra cứu gần như hằng số theo khóa.

And a bitmap — a string of n binary digits — is a compact way to track the status of n identical items at once, like which blocks of a disk are free.
