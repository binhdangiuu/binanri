Chapter 10.A · File-System Interface

What a file actually is to the OS, and how users reach it

Chapters 8–9 were about managing RAM. Chapter 10 moves to persistent storage: files that outlive any single process. This chapter is the user-facing side of the file system — what a file looks like from the outside (attributes, operations, locking, types, structure), how programs read/write it (access methods), how files are organized into directories, how separate file systems get mounted into one tree, how files are shared across users and networks, and how access is protected.

Chương 8–9 nói về quản lý RAM. Chương 10 chuyển sang bộ nhớ lưu trữ bền vững (persistent storage): các file tồn tại lâu hơn bất kỳ tiến trình nào. Chương này là mặt nhìn từ phía user của hệ thống file — file trông như thế nào từ bên ngoài (thuộc tính, thao tác, khóa file, loại file, cấu trúc), chương trình đọc/ghi nó ra sao (access methods), file được tổ chức vào thư mục thế nào, các hệ thống file riêng lẻ được gắn (mount) thành 1 cây thế nào, file được chia sẻ giữa người dùng và qua mạng ra sao, và quyền truy cập được bảo vệ thế nào.

Summary — Silberschatz Ch.10.A
  • A file is an abstract data type defined and implemented by the operating system. It is a sequence of logical records, which may be a byte, a line, or a more complex data item.
  • 1 file là 1 kiểu dữ liệu trừu tượng do hệ điều hành định nghĩa và cài đặt. Nó là 1 chuỗi các logical record, có thể là 1 byte, 1 dòng, hoặc 1 mục dữ liệu phức tạp hơn.
  • A major task for the OS is to map the logical file concept onto physical storage devices such as hard disk or NVM device.
  • 1 nhiệm vụ chính của OS là ánh xạ khái niệm file logic lên thiết bị lưu trữ vật lý như ổ cứng hay thiết bị NVM.
  • Within a file system, directories organize files. A single-level directory in a multiuser system causes naming problems; a two-level directory solves this by giving each user their own directory.
  • Trong 1 hệ thống file, thư mục tổ chức các file. Thư mục 1 cấp trong hệ đa người dùng gây ra vấn đề trùng tên; thư mục 2 cấp giải quyết bằng cách cho mỗi user 1 thư mục riêng.
  • The natural generalization of a two-level directory is a tree-structured directory. Acyclic-graph structures let users share subdirectories and files but complicate searching and deletion; a general graph allows full flexibility but may need garbage collection.
  • Khái quát tự nhiên của thư mục 2 cấp là thư mục dạng cây. Cấu trúc acyclic-graph cho phép chia sẻ thư mục/file con nhưng khiến việc tìm kiếm và xóa phức tạp hơn; general graph cho sự linh hoạt tối đa nhưng có thể cần garbage collection.
  • Remote file systems present challenges in reliability, performance, and security. Distributed information systems maintain user, host, and access information so clients and servers can share state.
  • Hệ thống file từ xa (remote) đặt ra thách thức về độ tin cậy, hiệu năng và bảo mật. Hệ thống thông tin phân tán duy trì thông tin user, host, quyền truy cập để client/server chia sẻ trạng thái.
  • Since files are the main information-storage mechanism, file protection is needed on multiuser systems — controlled per type of access (read, write, execute, append, delete, list) via access lists, passwords, or other techniques.
  • Vì file là cơ chế lưu trữ thông tin chính, bảo vệ file là cần thiết trên hệ đa người dùng — kiểm soát theo từng loại truy cập (đọc, ghi, thực thi, append, xóa, liệt kê) qua access list, mật khẩu, hoặc kỹ thuật khác.

1File Concept: hộp chứa có địa chỉ liên tục

A file is a named collection of related information recorded on secondary storage — a contiguous logical address space. Files may be free-form (e.g. text) or formatted rigidly (e.g. fixed fields).

1 file là 1 tập hợp thông tin liên quan, có tên, được ghi trên bộ nhớ phụ — 1 không gian địa chỉ logic liên tục. File có thể tự do định dạng (văn bản) hoặc định dạng chặt (các trường cố định).
📦
Ví dụ đời thườngGiống 1 cái hộp carton chuyển nhà: OS chỉ quan tâm cái hộp có tên gì, nằm đâu, to bao nhiêu — không quan tâm bên trong là sách, quần áo hay đồ bếp. Người đóng gói (chương trình tạo file) mới là người biết bên trong là gì.
Hình 1 · A file = contiguous logical address spaceFile là 1 dãy ô liên tục; cùng 1 vùng byte, mỗi chương trình hiểu 1 kiểu khác nhau — OS không quan tâm ý nghĩa.

Files can hold many types of content, defined entirely by the file's creator: data files (numeric, character, binary — complex or simple) and program files (source code, object code, executables).

File có thể chứa nhiều loại nội dung, hoàn toàn do người tạo quyết định: file dữ liệu (số, ký tự, nhị phân — phức tạp hoặc đơn giản) và file chương trình (mã nguồn, mã đối tượng, file thực thi).
Data file

Numeric, character, binary, hoặc cấu trúc phức tạp (ảnh, âm thanh, cơ sở dữ liệu).

Program file

Text file (văn bản thuần), source file (mã nguồn), executable file (file thực thi).

2File Attributes: "lý lịch" của file, không nằm trong nội dung

A file has attributes — metadata that varies across operating systems but typically includes: name, identifier, type, location, size, protection, and time/date/user ID information.

1 file có các thuộc tính (attributes) — metadata thay đổi tùy hệ điều hành nhưng thường gồm: tên, identifier, loại, vị trí, kích thước, bảo vệ, và thông tin thời gian/ngày/user.
Name

Thông tin duy nhất được lưu ở dạng con người đọc được.

Identifier

Thẻ (số) duy nhất xác định file trong hệ thống file.

Type

Cần thiết cho hệ hỗ trợ nhiều loại file khác nhau.

Location

Con trỏ tới vị trí file trên thiết bị lưu trữ.

Size

Kích thước hiện tại của file.

Protection

Kiểm soát ai được đọc, ghi, thực thi.

Time/Date/User ID

Dữ liệu phục vụ bảo vệ, bảo mật, và theo dõi sử dụng.

This information is kept in the directory structure, which is itself maintained on the disk. Many systems add extended attributes, such as a file checksum.

Thông tin này được lưu trong cấu trúc thư mục (directory structure), bản thân cấu trúc này cũng được duy trì trên đĩa. Nhiều hệ thống còn thêm thuộc tính mở rộng, như checksum của file.

3File Operations: file là 1 kiểu dữ liệu trừu tượng (ADT)

Hình 3 · File operations over a lifecycleVòng đời file: create → open → read/write/seek → close → delete; open/close giúp tránh tra thư mục mỗi lần truy cập.

A file is an abstract data type — the OS provides basic operations as system calls.

1 file là 1 kiểu dữ liệu trừu tượng (ADT) — OS cung cấp các thao tác cơ bản dưới dạng system call.
🎛️
Ví dụ đời thườngGiống điều khiển TV: bạn chỉ cần biết các nút bấm (bật, tăng âm, chuyển kênh), không cần biết mạch điện bên trong. File cũng vậy — bạn chỉ dùng các system call, OS lo phần còn lại.

Creating and removing: create makes a new file; delete removes it and frees its space; truncate erases the contents but keeps the attributes.

Tạo và xóa: create tạo file mới; delete xóa file và giải phóng chỗ; truncate xóa nội dung nhưng giữ nguyên thuộc tính.
🧽
Ví dụ đời thườngGiống 1 quyển vở: create = mua vở mới; delete = vứt cả quyển; truncate = tẩy sạch chữ nhưng vẫn giữ quyển vở và cái bìa có tên bạn.

Reading and writing: write puts data at the write pointer, read gets data at the read pointer, and reposition (seek) moves the pointer within the file.

Đọc và ghi: write ghi dữ liệu tại con trỏ ghi, read đọc dữ liệu tại con trỏ đọc, và reposition (seek) dời con trỏ trong file.
🔖
Ví dụ đời thườngGiống cái bookmark trong cuốn sách: read/write làm việc tại chỗ kẹp bookmark, còn seek là bạn lật tay kẹp bookmark sang 1 trang khác.
open(Fi)

Tìm cấu trúc thư mục trên đĩa cho mục Fi, và chuyển nội dung mục đó vào bộ nhớ.

close(Fi)

Chuyển nội dung mục Fi trong bộ nhớ trở lại cấu trúc thư mục trên đĩa.

4Open Files: dữ liệu OS phải theo dõi khi file đang mở

Several pieces of data are needed to manage open files. First, an open-file table tracks every open file, and a file pointer (kept per process) points to the last read/write location.

Có nhiều dữ liệu cần theo dõi để quản lý file đang mở. Trước hết, 1 open-file table theo dõi mọi file đang mở, và 1 con trỏ file (giữ riêng cho mỗi tiến trình) trỏ tới vị trí đọc/ghi gần nhất.
📋
Ví dụ đời thườngGiống sổ mượn sách ở thư viện: sổ chung ghi mọi cuốn đang được mượn, còn mỗi bạn có 1 tờ giấy nhớ riêng ghi đang đọc tới trang mấy.

Next, a file-open count keeps the table entry alive until the last process closes the file.

Tiếp theo, 1 file-open count giữ mục trong bảng cho tới khi tiến trình cuối cùng đóng file.
🚪
Ví dụ đời thườngGiống đèn phòng họp: 3 người cùng ở trong thì phải đợi người cuối cùng ra khỏi phòng mới tắt đèn — đếm người (open count) về 0 thì mới tắt.

Finally, the disk location of the file is cached for fast access, and access rights are stored per process as access-mode information.

Cuối cùng, vị trí trên đĩa của file được cache để truy cập nhanh, và quyền truy cập được lưu theo từng tiến trình dưới dạng thông tin chế độ truy cập.
📍
Ví dụ đời thườngGiống lưu địa chỉ nhà bạn vào Google Maps (cache) để khỏi phải tra lại mỗi lần đi, và thẻ ra vào ghi rõ bạn được vào khu nào (quyền truy cập).
Open-file table

Theo dõi các file đang mở trong hệ thống.

File pointer

Con trỏ vị trí đọc/ghi cuối, riêng cho mỗi tiến trình.

File-open count

Đếm số lần file đang được mở — xóa mục bảng khi về 0.

Disk location

Cache thông tin truy cập dữ liệu trên đĩa.

Access rights

Chế độ truy cập theo từng tiến trình.

5Open File Locking: tránh 2 tiến trình giẫm chân nhau

Hình 5 · Shared vs exclusive lock timelineNhiều reader cùng giữ shared lock được; writer cần exclusive nên phải đợi hết reader, trong lúc đó reader mới bị chặn.

Some operating systems/file systems provide open file locking — similar to reader-writer locks.

Một số OS/hệ thống file cung cấp khóa file đang mở (open file locking) — tương tự reader-writer lock.
🔐
Ví dụ đời thườngGiống phòng đọc sách: nhiều người cùng đọc được 1 cuốn tài liệu, nhưng khi có người xin sửa thì phải đợi mọi người đọc xong.

A shared lock is like a reader lock: several processes can acquire it concurrently.

Shared lock giống reader lock: nhiều tiến trình có thể acquire cùng lúc.
📖
Ví dụ đời thườngGiống nhiều bạn cùng xem 1 bảng điểm dán ở cửa lớp — ai cũng đọc được cùng lúc, không ai cản ai.

An exclusive lock is like a writer lock: only one process may hold it, and no one else may read or write meanwhile.

Exclusive lock giống writer lock: chỉ 1 tiến trình được giữ, và trong lúc đó không ai khác được đọc hay ghi.
🚧
Ví dụ đời thườngGiống phòng thay đồ: 1 người vào thì khóa cửa lại, người khác phải đứng ngoài đợi tới khi người đó ra.
Mandatory locking

Quyền truy cập bị từ chối tùy theo khóa đang giữ và khóa đang yêu cầu — hệ thống tự enforce.

Advisory locking

Tiến trình có thể kiểm tra trạng thái khóa và tự quyết định làm gì — không bị ép buộc.

File locking mediates access to a file, so 2 processes don't corrupt each other's writes. The Java API example below locks the first half of a file exclusively, then the second half with a shared lock.

File locking làm trung gian cho việc truy cập file, để 2 tiến trình không ghi đè làm hỏng dữ liệu của nhau. Ví dụ Java API dưới đây khóa exclusive nửa đầu file, rồi khóa shared nửa sau; khối finally luôn release lock dù có lỗi.
Java API — FileLock example
FileChannel ch = raf.getChannel();
FileLock exclusiveLock = null, sharedLock = null;
try {
    // locks the first half of the file — exclusive
    exclusiveLock = ch.lock(0, raf.length()/2, EXCLUSIVE);
    /* modify the data ... */

    // locks the second half of the file — shared
    sharedLock = ch.lock(raf.length()/2+1, raf.length(), SHARED);
    /* read the data ... */
} catch (IOException ioe) {
    System.err.println(ioe);
} finally {
    // always release, even if an exception occurred
    if (exclusiveLock != null) exclusiveLock.release();
    if (sharedLock != null) sharedLock.release();
}

7File Structure: ai quyết định cấu trúc bên trong?

File structure ranges from none (just a sequence of words or bytes) to simple record structures (lines, fixed length, variable length) to complex structures (formatted documents, relocatable load files).

Cấu trúc file trải dài từ none (chỉ là chuỗi word hoặc byte) tới cấu trúc record đơn giản (dòng, độ dài cố định, độ dài thay đổi) tới cấu trúc phức tạp (tài liệu định dạng, file thực thi relocatable).
🧱
Ví dụ đời thườngGiống đồ xếp hình: loại đơn giản như 1 đống gạch rời, loại record như gạch xếp thành hàng đều, loại phức tạp như cả 1 mô hình lâu đài đã lắp sẵn.

A plain sequence of bytes (the "none" structure) can simulate the last two — simple records and complex structures — by inserting appropriate control characters.

Chuỗi byte trần (cấu trúc "none") có thể mô phỏng 2 loại sau (record đơn giản và cấu trúc phức tạp) bằng cách chèn ký tự điều khiển phù hợp.
✂️
Ví dụ đời thườngGiống file văn bản .txt dùng ký tự xuống dòng (\n) để "giả" thành các dòng — dòng không có thật trong dữ liệu, chỉ là quy ước bằng ký tự đặc biệt.

Who decides how a file is interpreted — the structure's owner? Two main approaches exist.

Ai quyết định cách diễn giải file — chủ của cấu trúc đó? Có 2 hướng chính.
🤔
Ví dụ đời thườngGiống câu hỏi "ai quyết định cách xếp đồ trong hộp": người làm hộp (OS) hay người cất đồ vào (chương trình)?

Approach 1: the operating system supports only a minimal number of file structures (as in UNIX/Windows).

Hướng 1: hệ điều hành chỉ hỗ trợ 1 số ít cấu trúc file tối thiểu (như UNIX/Windows).
📮
Ví dụ đời thườngGiống bưu điện: chỉ biết "thư" và "bưu kiện", không quan tâm bên trong chứa gì — ít loại nên đơn giản, ai cũng gửi được.

Approach 2: leave it entirely to the application program, which is responsible for interpreting the file's contents.

Hướng 2: để hoàn toàn cho chương trình ứng dụng tự diễn giải nội dung file.

02 · Cách đọc/ghi

Information in a file can be accessed sequentially, or jumped to directly

Thông tin trong 1 file có thể được truy cập tuần tự, hoặc nhảy thẳng tới vị trí cần

Files store information, but the way a program reads that information back matters a lot for performance. The OS offers a handful of access patterns.

File lưu trữ thông tin, nhưng cách 1 chương trình đọc lại thông tin đó ảnh hưởng rất nhiều tới hiệu năng. OS cung cấp 1 số kiểu truy cập.

1Sequential Access: đọc từ đầu tới cuối, như băng cassette

Sequential access is based on a tape model of a file — operations are read next and write next.

Sequential access dựa trên mô hình băng từ (tape) của 1 file — thao tác là read next và write next.
▶️
Ví dụ đời thườngGiống nghe radio: nghe hết bài này mới tới bài sau, không nhảy cóc được.

A reset moves back to the beginning; some systems also allow skipping forward/backward n records (rarely needed after rewind). Note: no read after last write (rewrite).

reset đưa về đầu; 1 số hệ cho phép nhảy tới/lùi n record (nhưng hiếm khi cần sau khi rewind). Lưu ý: không đọc sau lần ghi cuối (rewrite).
⏪
Ví dụ đời thườngGiống bấm nút tua lại băng cassette về đầu để nghe lại từ bài 1.
📼

2Direct Access: nhảy thẳng tới block cần, như đĩa CD

A file is made of fixed-length logical records that allow programs to read/write records rapidly, in no particular order.

File gồm các logical record có độ dài cố định, cho phép chương trình đọc/ghi record nhanh, theo thứ tự bất kỳ.
🗄️
Ví dụ đời thườngGiống tủ hồ sơ có các ngăn đánh số cùng kích thước: muốn lấy hồ sơ ngăn số 7 thì mở thẳng ngăn 7, không cần mở 6 ngăn trước.

Direct access is based on a disk model of a file, since disks allow random access to any file block.

Direct access dựa trên mô hình đĩa (disk) của 1 file, vì đĩa cho phép truy cập ngẫu nhiên tới bất kỳ block nào của file.
💿
Ví dụ đời thườngGiống việc chọn bài hát trên đĩa CD hoặc file MP3: bạn bấm thẳng vào bài số 8 là đầu đọc nhảy ngay tới đó, không cần tua qua 7 bài trước — khác hẳn băng cassette.
Hình 9 · Direct access: jump straight to block nread n / write n nhảy thẳng tới block n, không cần đọc các block trước đó — phù hợp CSDL, tìm kiếm ngẫu nhiên.

Operations include: read n, write n, position to n then read/write next, read next, write next, and rewrite n.

Thao tác gồm: read n, write n, position to n rồi đọc/ghi tiếp, read next, write next, và rewrite n.
🔢
Ví dụ đời thườngGiống mở YouTube: bấm thẳng phút thứ 30 (read n), hoặc cứ để video chạy tiếp (read next).

Here n is the relative block number, an index relative to the beginning of the file.

Ở đây n là relative block number, 1 chỉ số tương đối tính từ đầu file.
🏠
Ví dụ đời thườngGiống số nhà trong 1 con hẻm: "căn số 5 của hẻm" — số 5 tính từ đầu hẻm, chưa phải địa chỉ thật của cả thành phố.

Relative block numbers let the OS decide where the file is actually placed on disk (the real allocation problem, covered in Chapter 11/12).

Relative block number cho phép OS tự quyết định file thực sự được đặt ở đâu trên đĩa (bài toán cấp phát thật sự, học ở Chương 11/12).
🏨
Ví dụ đời thườngGiống khách đặt "phòng số 3 của đoàn": khách sạn tự quyết định đó là phòng nào ở tầng nào — khách không cần biết.

If the index is too large, an index of the index is kept on disk.

Nếu index quá lớn, giữ 1 index của index đó trên đĩa.
📚

📇

03 · Tổ chức file

Disks hold partitions, partitions hold volumes, volumes hold a directory tree

Đĩa chứa partition, partition chứa volume, volume chứa 1 cây thư mục

Before talking about directories, we need to know where they physically live: on disk, organized into partitions and volumes.

Trước khi nói về thư mục, cần biết chúng thực sự nằm ở đâu: trên đĩa, được tổ chức thành partition và volume.

1Disk Structure: partition, RAID, raw vs formatted, volume

A disk can be subdivided into partitions (also known as minidisks, slices); disks or partitions can be RAID-protected against failure.

1 đĩa có thể được chia thành các partition (còn gọi là minidisk, slice); đĩa hoặc partition có thể được bảo vệ chống lỗi bằng RAID.
🛡️
Ví dụ đời thườngGiống chia 1 ổ cứng thành ổ C: và D:; RAID giống việc photo giấy tờ quan trọng làm 2 bản, 1 bản hỏng vẫn còn bản kia.

A disk or partition can be used raw (without a file system) or formatted with a file system.

1 đĩa hoặc partition có thể dùng ở dạng raw (không có hệ thống file) hoặc formatted (đã có hệ thống file).
📓
Ví dụ đời thườngGiống tờ giấy trắng (raw) so với cuốn vở đã kẻ dòng và đánh số trang (formatted): vở có cấu trúc sẵn để ghi chép gọn gàng.

The entity containing a file system is known as a volume; each volume also tracks its file system's info in a device directory or volume table of contents.

Thực thể chứa 1 hệ thống file được gọi là volume; mỗi volume cũng theo dõi thông tin hệ thống file của nó trong device directory hoặc volume table of contents.

A typical file-system organization spreads directories and files across several partitions on several disks.

1 tổ chức hệ thống file điển hình trải directory và file ra nhiều partition trên nhiều đĩa.
🏢
Ví dụ đời thườngGiống 1 tòa chung cư (đĩa vật lý) được chia thành nhiều căn hộ (partition); mỗi căn hộ (volume) có sổ hộ khẩu riêng (device directory) ghi ai đang ở, phòng nào chứa gì.
Hình 12 · Disk structure: partition, volume, rawĐĩa chia thành partition; partition có FS = volume (kèm device directory), partition raw dùng cho swap/CSDL.

Beyond general-purpose file systems, many special-purpose file systems coexist within the same OS — e.g. Solaris has tmpfs (memory-based, volatile, for fast temporary I/O) and procfs (kernel interface to process structures).

Bên cạnh các hệ thống file đa dụng, nhiều hệ thống file chuyên dụng cùng tồn tại trong 1 OS — ví dụ Solaris có tmpfs (dựa trên bộ nhớ, dễ mất, cho I/O tạm nhanh) và procfs (giao diện kernel tới cấu trúc tiến trình).
📝
Ví dụ đời thườngtmpfs giống bảng trắng trong phòng họp: viết nhanh, tắt điện là mất. procfs giống bảng điều khiển ô tô: không chứa "file thật" mà cho bạn xem trạng thái của máy.

Others include objfs (kernel symbols for debugging), ctfs (contract FS for managing daemons), lofs (loopback FS), and the general-purpose ufs, zfs.

Các loại khác gồm objfs (ký hiệu kernel để debug), ctfs (quản lý daemon), lofs (loopback FS), và ufs, zfs đa dụng.
🧰
Ví dụ đời thườngGiống bộ dụng cụ: mỗi hệ thống file là 1 dụng cụ chuyên dụng (tuốc-nơ-vít, kìm…), cùng nằm trong 1 hộp đồ nghề là hệ điều hành.

2Directory: "sổ mục lục" liên kết tên tới file

A directory is a collection of nodes containing information about all files — both the directory structure and the files themselves reside on disk.

1 directory là tập hợp các node chứa thông tin về tất cả file — cả cấu trúc thư mục lẫn file đều nằm trên đĩa.
📒
Ví dụ đời thườngGiống mục lục sách: mục lục nằm trong chính cuốn sách (trên đĩa), liệt kê từng chương nằm ở đâu.

The operations on a directory include: search for a file, create, delete, list a directory, rename, and traverse the file system.

Các thao tác trên thư mục gồm: search (tìm) file, create (tạo), delete (xóa), list (liệt kê) thư mục, rename (đổi tên), và traverse (duyệt) hệ thống file.
🔍
Ví dụ đời thườngGiống thao tác trong Windows Explorer: tìm file (Ctrl+F), tạo thư mục mới, xóa, xem danh sách, đổi tên (F2), và bấm vào từng thư mục để duyệt.

The directory is organized logically to obtain efficiency — locating a file quickly.

Thư mục được tổ chức logic để đạt hiệu quả — tìm file nhanh.
⚡
Ví dụ đời thườngGiống tủ quần áo xếp theo loại: tìm cái áo sơ mi mất 3 giây, thay vì lục cả đống đồ lộn xộn.

Naming should be convenient to users — 2 users can have the same name for different files, and the same file can have several different names.

Đặt tên phải thuận tiện cho user — 2 user có thể trùng tên cho 2 file khác nhau; cùng 1 file có thể có nhiều tên khác nhau.
🧠
Ví dụ đời thườngGiống 2 bạn cùng có file "baitap.docx" nhưng trong 2 máy riêng; còn 1 người có thể có tên thật và biệt danh cùng chỉ 1 người.

Grouping means logically grouping files by properties, e.g. all Java programs, all games.

Nhóm nghĩa là gom nhóm file theo tính chất, ví dụ: tất cả chương trình Java, tất cả game.
🗃️
Ví dụ đời thườngGiống thư viện nhạc: gom theo thể loại (Pop, Rock, Nhạc phim) để dễ chọn.

Single-Level Directory: a single directory for all users. This is naive and has significant problems when there is more than one user.

Thư mục 1 cấp: 1 thư mục duy nhất cho mọi user. Đơn giản nhưng gặp vấn đề lớn khi có hơn 1 user.

The naming problem: 2 users can't have files with the same name.

Vấn đề trùng tên: 2 user không thể có file cùng tên.
👕

Vấn đề nhóm: không cách nào tổ chức file theo loại.
🌀

🧺

Two-Level Directory: a separate directory for each user — a master file directory (MFD) lists each user, and each user has their own user file directory (UFD).

Thư mục 2 cấp: 1 thư mục riêng cho mỗi user — master file directory (MFD) liệt kê từng user, mỗi user có user file directory (UFD) riêng.

Now files can have the same name across different users, and searching is efficient.

Giờ file có thể trùng tên giữa các user khác nhau, tìm kiếm hiệu quả.
🏘️
Ví dụ đời thườngGiống nhà ở khu dân cư: mỗi nhà có tủ riêng, hai nhà cùng có "chai nước mắm" cũng không nhầm.

But there is still no grouping capability within a single user's directory.

Nhưng vẫn không có khả năng nhóm trong chính thư mục của 1 user.
🎒
Ví dụ đời thườngGiống tủ riêng của bạn có đủ thứ nhưng không có ngăn: sách, đồ chơi, giấy tờ vẫn lẫn vào nhau.
🏫
Ví dụ đời thườngGiống 1 khách sạn: lễ tân (MFD) biết phòng của mỗi khách; mỗi khách có phòng riêng (UFD) để chứa đồ riêng, 2 khách có thể cùng mang theo 1 cái "vali" mà không trùng nhau. Nhưng trong phòng của 1 khách, đồ vẫn vứt lẫn lộn, không chia thành nhiều ngăn.

Every file has a unique path name — absolute (from the root) or relative (from the current directory, also called working directory).

Mỗi file có 1 path name duy nhất — tuyệt đối (absolute) (từ root) hoặc tương đối (relative) (từ current directory, còn gọi là working directory).

Creating a new file or subdirectory is done in the current directory.

Tạo file hoặc thư mục con mới được thực hiện trong current directory.

🗑️
