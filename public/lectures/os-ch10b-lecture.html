Summary — Silberschatz Ch.10.B
  • Most file systems reside on secondary storage, designed to hold large amounts of data permanently. The most common medium is the disk, but NVM devices are increasing.
  • Hầu hết hệ thống file nằm trên bộ nhớ phụ, thiết kế để giữ lượng dữ liệu lớn lâu dài. Phương tiện phổ biến nhất là đĩa, nhưng thiết bị NVM đang tăng.
  • Storage devices are divided into partitions so that multiple, possibly different, file systems can share one device; they are mounted onto a logical file-system architecture.
  • Thiết bị lưu trữ được chia thành các partition để nhiều hệ thống file (có thể khác loại) dùng chung 1 thiết bị; chúng được mount vào 1 kiến trúc hệ thống file logic.
  • File systems are often layered: lower levels deal with physical devices, upper levels deal with symbolic file names and logical properties.
  • Hệ thống file thường chia tầng: tầng dưới lo thiết bị vật lý, tầng trên lo tên file ký hiệu và tính chất logic.
  • Files are allocated space in 3 ways: contiguous (external fragmentation), linked (inefficient direct access), indexed (index-block overhead). Extents and clustering optimize them.
  • File được cấp chỗ theo 3 cách: contiguous (phân mảnh ngoài), linked (truy cập trực tiếp kém hiệu quả), indexed (tốn index block). Extent và clustering giúp tối ưu.
  • Free-space methods include bit vectors and linked lists; optimizations include grouping, counting and the FAT, which puts the linked list in one contiguous area.
  • Các cách quản lý chỗ trống gồm bit vector và linked list; tối ưu có grouping, counting và FAT (đặt linked list trong 1 vùng liên tục).
  • A hash table is a common, fast directory method, but damage to it or a crash can make directory info inconsistent with the disk. A consistency checker repairs damage; backups recover from data or device loss.
  • Hash table là cách lưu thư mục phổ biến và nhanh, nhưng hỏng bảng hoặc sập máy có thể làm thông tin thư mục lệch với đĩa. Consistency checker sửa hỏng hóc; backup giúp phục hồi khi mất dữ liệu hay thiết bị.
  • Performance and reliability are crucial: log structures and caching improve performance; log structures and RAID improve reliability. WAFL is an example of optimizing for a specific I/O load.
  • Hiệu năng và độ tin cậy rất quan trọng: log structure và caching cải thiện hiệu năng; log structure và RAID cải thiện độ tin cậy. WAFL là ví dụ tối ưu cho 1 tải I/O cụ thể.

02 · Cài đặt tầng thấp

From user API down to blocks: how a file system is built

Từ API của user xuống tới block: hệ thống file được xây thế nào

Chapter 10.A showed what files look like. Here we look inside: how the OS actually stores files on disk and which structures it keeps in memory.

Chương 10.A cho thấy file trông như thế nào. Ở đây ta nhìn bên trong: OS thực sự lưu file trên đĩa ra sao và giữ những cấu trúc nào trong bộ nhớ.

1File-System Structure: từ file logic tới block vật lý

A file system resides on secondary storage (e.g. disks). It gives users a clean interface and maps logical files to physical blocks, so data can be stored, located and retrieved easily.

Hệ thống file nằm trên bộ nhớ phụ (ví dụ đĩa). Nó cho user 1 giao diện gọn và ánh xạ file logic sang block vật lý, để dữ liệu được lưu, tìm và lấy dễ dàng.
📚
Ví dụ đời thườngGiống thư viện: bạn chỉ nói "cho tôi quyển Giải tích 1", thủ thư tự biết quyển đó nằm ở kệ nào, tầng mấy.

A disk provides in-place rewrite and random access, and I/O is done in blocks of sectors (usually 512 bytes).

Đĩa cho phép ghi đè tại chỗ (in-place rewrite) và truy cập ngẫu nhiên; I/O thực hiện theo block gồm các sector (thường 512 byte).
🍫
Ví dụ đời thườngGiống thanh sô-cô-la chia thành các ô vuông: bạn không bẻ từng vụn nhỏ, mà luôn bẻ nguyên 1 ô (block) mỗi lần.

A file control block (FCB) stores all information about one file, and a device driver controls the physical device.

1 file control block (FCB) lưu toàn bộ thông tin về 1 file, còn device driver điều khiển thiết bị vật lý.
🪪
Ví dụ đời thườngFCB giống hồ sơ cá nhân của 1 file (tên, chủ, quyền, ngày, địa chỉ); device driver giống phiên dịch viên nói chuyện trực tiếp với từng loại ổ đĩa.

2Layered File System: 5 tầng chia việc

The file system is organized into layers. Layering reduces complexity and redundancy, but adds overhead and can reduce performance.

Hệ thống file được tổ chức thành các tầng (layer). Chia tầng giảm độ phức tạp và trùng lặp, nhưng thêm overhead và có thể giảm hiệu năng.
🏢
Ví dụ đời thườngGiống tòa nhà công ty nhiều phòng ban: mỗi phòng làm 1 việc nên gọn, nhưng 1 yêu cầu phải đi qua nhiều phòng nên chậm hơn làm 1 mình.
Hình 1 · Layered file systemYêu cầu đi từ trên xuống: logical FS → file-organization → basic FS → I/O control → thiết bị; mỗi tầng chỉ nói chuyện với tầng kề.

I/O control = device drivers. Given a command like "read drive1, cylinder 72, track 2, sector 10, into memory location 1060", it outputs low-level hardware-specific commands to the controller.

I/O control = các device driver. Nhận lệnh như "read drive1, cylinder 72, track 2, sector 10, vào địa chỉ nhớ 1060", rồi sinh ra lệnh phần cứng mức thấp cho bộ điều khiển.
🚕
Ví dụ đời thườngGiống tài xế taxi: bạn nói "đến 268 Lý Thường Kiệt", tài xế (driver) lo chuyện rẽ trái, rẽ phải, đạp ga cụ thể.

The basic file system gets a command like "retrieve block 123" and passes it to the device driver. It also manages memory buffers and caches (allocation, freeing, replacement).

Basic file system nhận lệnh như "retrieve block 123" rồi chuyển cho device driver. Nó cũng quản lý buffer và cache trong bộ nhớ (cấp phát, giải phóng, thay thế).

Buffers hold data in transit; caches hold frequently used data.

Buffer giữ dữ liệu đang chuyển; cache giữ dữ liệu hay dùng.
🛒
Ví dụ đời thườngBuffer giống xe đẩy ở siêu thị: để hàng tạm trên đường ra quầy. Cache giống kệ "hàng bán chạy" đặt sát cửa để lấy cho nhanh.

The file-organization module knows files, logical addresses and physical blocks. It translates logical block # to physical block # and manages free space and disk allocation.

File-organization module hiểu file, địa chỉ logic và block vật lý. Nó dịch số block logic sang số block vật lý và quản lý chỗ trống, cấp phát đĩa.
🏨
Ví dụ đời thườngGiống lễ tân khách sạn: khách chỉ nói "phòng thứ 3 của đoàn", lễ tân tra bảng để ra phòng thật 405.

The logical file system manages metadata: it translates a file name into a file number / file handle / location by maintaining FCBs (inodes in UNIX), and handles directory management and protection.

Logical file system quản lý metadata: dịch tên file thành file number / file handle / vị trí bằng cách duy trì các FCB (inode trong UNIX), đồng thời lo quản lý thư mục và bảo vệ.
📇
Ví dụ đời thườngGiống phòng tiếp nhận hồ sơ: bạn đưa tên, phòng tra sổ rồi trao số hồ sơ + kiểm tra bạn có quyền xem hay không.

3Many File Systems: mỗi loại 1 định dạng

Many file systems exist within an OS, each with its own format: CD-ROM uses ISO 9660; UNIX has UFS and FFS; Windows has FAT, FAT32, NTFS.

Nhiều hệ thống file cùng tồn tại trong 1 OS, mỗi loại có định dạng riêng: CD-ROM dùng ISO 9660; UNIX có UFS, FFS; Windows có FAT, FAT32, NTFS.

Linux supports more than 130 types, with ext3 and ext4 leading, plus distributed file systems such as NFS.

Linux hỗ trợ hơn 130 loại, trong đó ext3, ext4 phổ biến nhất, cộng thêm hệ thống file phân tán như NFS.
🔌
Ví dụ đời thườngGiống các loại ổ cắm điện khác nhau (2 chân, 3 chân, USB-C): thiết bị là cùng 1 máy, nhưng mỗi chuẩn cần 1 "đầu cắm" (driver FS) riêng.

4On-Disk Structures: 4 thứ nằm trên đĩa

System calls exist at the API level — but how are their functions implemented? Using structures kept on disk and in memory.

Các system call có ở mức API — nhưng chúng được cài đặt thế nào? Bằng các cấu trúc lưu trên đĩa và trong bộ nhớ.

The boot control block holds the info needed to boot an OS from that volume — usually the first block of the volume, needed only if the volume contains an OS.

Boot control block chứa thông tin cần để khởi động OS từ volume đó — thường là block đầu tiên của volume, chỉ cần khi volume có chứa OS.
🔑
Ví dụ đời thườngGiống chìa khóa cổng chính: không có nó thì không vào được nhà để bật điện (boot OS).

The volume control block (superblock, or master file table) holds volume details: total # of blocks, # of free blocks, block size, free-block pointers or array.

Volume control block (superblock, hoặc master file table) chứa thông tin volume: tổng số block, số block trống, kích thước block, con trỏ/mảng free block.
📋
Ví dụ đời thườngGiống bảng thông tin chung cư ở sảnh: tổng số căn, còn bao nhiêu căn trống, diện tích mỗi căn.

The directory structure organizes the files (names and inode numbers, or the master file table).

Cấu trúc thư mục tổ chức các file (tên và số inode, hoặc master file table).

The per-file FCB holds inode number, permissions, size, dates. NTFS stores this in the master file table using relational-DB structures.

FCB của từng file chứa số inode, quyền, kích thước, ngày tháng. NTFS lưu trong master file table theo cấu trúc kiểu CSDL quan hệ.
Hình 2 · On-disk file system layoutĐầu volume là boot + control block; tiếp theo là thư mục và FCB/inode; phần còn lại là các block dữ liệu của file.
Hình 3 · Inside a file control blockFCB (inode) giữ metadata của file và các con trỏ tới block dữ liệu — nội dung file không nằm trong FCB.

5In-Memory Structures: mở file thì RAM giữ gì?

In memory the OS keeps a mount table (file system mounts, mount points, types), a system-wide open-file table (a copy of each open file's FCB) and a per-process open-file table (pointers into the system-wide table).

Trong RAM, OS giữ mount table (các lần mount, mount point, loại FS), system-wide open-file table (bản sao FCB của mỗi file đang mở) và per-process open-file table (con trỏ tới bảng hệ thống).
📒
Ví dụ đời thườngGiống sổ mượn sách của thư viện: 1 sổ chung ghi mọi sách đang cho mượn, và mỗi bạn đọc có 1 phiếu nhỏ chỉ tới dòng tương ứng trong sổ chung.

open() returns a file handle for later use. First the system searches the directory, copies the FCB into the system-wide table, then adds an entry in the per-process table.

open() trả về 1 file handle để dùng về sau. Hệ thống tìm trong thư mục, chép FCB vào bảng hệ thống, rồi thêm 1 mục vào bảng của tiến trình.
Hình 4 · Opening a fileopen() tìm thư mục → nạp FCB vào system-wide table → tạo entry per-process → trả file handle cho user.
🎟️
Ví dụ đời thườngGiống lấy số thứ tự ở phòng khám: lần đầu cần tra hồ sơ (chậm), sau đó chỉ cần đưa số thứ tự (handle) là được gọi ngay.

read() uses the handle to jump straight to the FCB (no directory search again). Data blocks from disk go into buffers, then are copied to the specified user-process memory address.

read() dùng handle nhảy thẳng tới FCB (không tìm lại thư mục). Block dữ liệu từ đĩa vào buffer, rồi được chép tới địa chỉ nhớ user chỉ định.
Hình 5 · Reading a fileHandle → entry per-process → FCB → buffer cache → chép dữ liệu sang vùng nhớ của tiến trình user.
📬
Ví dụ đời thườngGiống nhận thư qua hộp thư chung: nhân viên (kernel) lấy thư từ kho (đĩa) về bàn (buffer), rồi bỏ vào hộp thư riêng của bạn (bộ nhớ user).

03 · Cài đặt thư mục

How directories are stored: list, hash table, B+ tree

Thư mục được lưu thế nào: danh sách, bảng băm, cây B+

Chapter 10.A taught directory structures (tree, graph). Now: what data structure holds the entries inside one directory?

Chương 10.A dạy các cấu trúc thư mục (cây, đồ thị). Giờ là: cấu trúc dữ liệu nào chứa các mục bên trong 1 thư mục?

1Linear List: danh sách tên + con trỏ

The simplest method is a linear list of file names, each with a pointer to the data blocks. It is simple to program.

Cách đơn giản nhất là danh sách tuyến tính (linear list) các tên file, mỗi tên kèm con trỏ tới block dữ liệu. Rất dễ lập trình.
🧠
Ví dụ đời thườngGiống cuốn sổ ghi tên bạn bè kèm số điện thoại theo thứ tự thêm vào: viết thêm rất dễ, ai cũng làm được.

But it is time-consuming to execute: searching takes linear time, because the OS must scan from the first entry. The list can be kept ordered via a linked list or a B+ tree.

Nhưng tốn thời gian khi chạy: tìm kiếm mất thời gian tuyến tính, vì OS phải quét từ mục đầu. Có thể giữ danh sách có thứ tự bằng linked list hoặc cây B+.
🔎
Ví dụ đời thườngMuốn tìm "Nguyễn Văn Bình" trong sổ không sắp xếp thì phải lật từng trang; nếu sổ sắp xếp theo vần (cây B+) thì mở thẳng chữ N.
Hình 6 · Linear list directoryMỗi mục = tên file + con trỏ block; tìm kiếm phải duyệt tuần tự từ đầu, độ phức tạp O(n).

2Hash Table: tính ra vị trí luôn

A hash table is a linear list plus a hash data structure: hash(file name) gives the position directly, which decreases directory search time.

Bảng băm (hash table) là linear list cộng cấu trúc hash: hash(tên file) cho ra ngay vị trí, nhờ đó giảm thời gian tìm trong thư mục.
🗄️
Ví dụ đời thườngGiống tủ có 8 ngăn đánh số: lấy tổng mã ký tự của tên, chia dư cho 8 ra số ngăn — mở thẳng ngăn đó, khỏi lục cả tủ.

Collisions occur when two file names hash to the same location. A hash table is only good if entries are fixed size, or if it uses the chained-overflow method.

Collision xảy ra khi 2 tên file băm ra cùng 1 vị trí. Hash table chỉ tốt khi các mục có kích thước cố định, hoặc dùng phương pháp chained-overflow (nối chuỗi tràn).
🚪
Ví dụ đời thườngGiống 2 người cùng được xếp vào phòng số 5: ghi thêm 1 chuỗi "người kế tiếp" sau phòng 5 để chứa người thứ hai.
Hình 7 · Hash table with collisionTên file → hash → ngăn; 2 tên cùng hash thì nối thêm vào chuỗi tràn của ngăn đó.

🛵

04 · Cấp phát block

Allocation methods: where do a file's blocks go on disk?

Phương pháp cấp phát: các block của file nằm ở đâu trên đĩa?

An allocation method decides how disk blocks are assigned to files. Three families: contiguous, linked, indexed — each trades speed, space and complexity differently.

1 phương pháp cấp phát quyết định cách gán block đĩa cho file. Có 3 họ: liên tục (contiguous), liên kết (linked), chỉ mục (indexed) — mỗi loại đánh đổi tốc độ, không gian và độ phức tạp khác nhau.

1Contiguous Allocation: mỗi file 1 dải liên tục

In contiguous allocation each file occupies a set of contiguous blocks. It gives the best performance in most cases and is simple: only the starting block # and the length are needed.

Ở cấp phát liên tục, mỗi file chiếm 1 tập block liên tiếp nhau. Hiệu năng tốt nhất trong đa số trường hợp và đơn giản: chỉ cần block bắt đầu và độ dài.
🎬
Ví dụ đời thườngGiống đặt 1 hàng ghế liền nhau ở rạp cho cả nhóm: chỉ cần nhớ "bắt đầu ghế 12, dài 5 ghế" — rất gọn, ngồi cạnh nhau xem rất tiện.
Hình 8 · Contiguous allocation and directory entryMỗi file chỉ cần (start, length) trong thư mục; file A bắt đầu 2 dài 3, file B bắt đầu 8 dài 3.

Mapping: with logical address LA and block size 512, compute Q = LA / 512 and R = LA mod 512. The block to access is Q + starting address, and the displacement into the block is R.

Ánh xạ: với địa chỉ logic LA và block 512, tính Q = LA / 512, R = LA mod 512. Block cần truy cập là Q + địa chỉ bắt đầu, độ dời trong block là R.
🏠
Ví dụ đời thườngGiống tìm phòng khi biết số đầu: bạn ở dãy bắt đầu từ phòng 100, muốn phòng thứ 5 của mình thì là 100 + 5 = 105. Cộng là xong.

Problems: finding space for a file, knowing the file size in advance, external fragmentation, and the need for compaction (off-line = downtime, or on-line).

Vấn đề: tìm chỗ cho file, biết trước kích thước file, phân mảnh ngoài, và cần compaction (off-line = phải dừng máy, hoặc on-line).
🅿️
Ví dụ đời thườngGiống bãi đỗ xe: các xe đi ra đi vào để lại nhiều ô trống lẻ; tổng trống đủ cho xe buýt nhưng không có chỗ nào liền nhau.
Hình 9 · External fragmentationTổng chỗ trống đủ (7 ô) nhưng bị chia thành các khe nhỏ → file 5 block liên tục không nhét vừa; phải compaction.

2Extent-Based Systems: contiguous nhưng linh hoạt

Many newer file systems (e.g. Veritas File System) use a modified contiguous scheme: they allocate in extents. An extent is a contiguous chunk of blocks, and a file consists of one or more extents.

Nhiều hệ thống file mới (ví dụ Veritas File System) dùng cách liên tục cải tiến: cấp phát theo extent. 1 extent là 1 cụm block liên tục, và 1 file gồm 1 hoặc nhiều extent.
🚆
Ví dụ đời thườngGiống thuê chỗ ngồi tàu: không cần cả nhóm ngồi 1 toa, chia 3 toa nhưng mỗi toa ngồi liền nhau là được.
Hình 10 · Extent-based allocationFile = danh sách extent; mỗi extent liên tục nhưng các extent có thể ở xa nhau → bớt phân mảnh, vẫn đọc nhanh.

3Linked Allocation: mỗi block trỏ block kế

In linked allocation each file is a linked list of blocks, scattered anywhere on the disk. Each block contains a pointer to the next; the file ends at a nil pointer. There is no external fragmentation and no compaction.

Ở cấp phát liên kết, mỗi file là 1 danh sách liên kết các block, nằm rải rác khắp đĩa. Mỗi block chứa con trỏ tới block kế; file kết thúc ở nil pointer. Không phân mảnh ngoài và không cần compaction.
🗺️
Ví dụ đời thườngGiống trò săn kho báu: mỗi mảnh giấy ghi manh mối chỗ giấu mảnh kế tiếp; không cần các mảnh nằm gần nhau, chỉ cần đi theo chuỗi.
Hình 11 · Linked allocationBlock rải rác; mỗi block có ô con trỏ tới block tiếp theo; thư mục chỉ giữ block đầu (và cuối).

When a file needs a new block, the free-space management system is called to supply one, and the new block is linked onto the end of the chain.

Khi file cần block mới, hệ thống quản lý chỗ trống được gọi để cấp 1 block, rồi block đó được nối vào cuối chuỗi.

Drawbacks: locating the Qth block can take many I/Os and seeks; reliability is a problem (one lost pointer breaks the chain); each block loses space to the pointer.

Nhược điểm: tìm block thứ Q có thể tốn nhiều I/O và seek; độ tin cậy kém (mất 1 con trỏ là đứt chuỗi); mỗi block mất chỗ cho con trỏ.

Mapping: Q = LA / 511, R = LA mod 511; read the Qth block in the chain, displacement R + 1.

Ánh xạ: Q = LA / 511, R = LA mod 511; đọc block thứ Q trong chuỗi, độ dời R + 1.
📞
Ví dụ đời thườngGiống tìm người qua chuỗi giới thiệu: muốn gặp người thứ 8 trong chuỗi thì phải gọi qua 7 người trước, người nào lạc số là đứt cả chuỗi.

Improvement: cluster blocks into groups — fewer pointers and fewer seeks, but more internal fragmentation.

Cải tiến: gom block thành cụm (cluster) — ít con trỏ và ít seek hơn, nhưng tăng phân mảnh trong.
📦
Ví dụ đời thườngGiống đóng hàng theo thùng 12 chai thay vì lẻ từng chai: ít phải đếm hơn, nhưng thùng chỉ có 1 chai cũng chiếm nguyên 1 thùng (phí chỗ).

4File Allocation Table (FAT): đưa con trỏ ra 1 bảng

The FAT variation puts the pointers in a table at the beginning of the volume, indexed by block number. It works like a linked list, but is faster on disk and cacheable, and new-block allocation is simple (find a 0 entry).

Biến thể FAT đưa các con trỏ vào 1 bảng ở đầu volume, đánh chỉ số theo số block. Hoạt động như linked list, nhưng nhanh hơn trên đĩa và cache được, cấp block mới đơn giản (tìm mục có giá trị 0).
📑
Ví dụ đời thườngGiống mục lục sách ghi "chương 1 → trang 5 → trang 9 → hết": bạn lướt mục lục (nằm ở đầu sách, dễ cache) thay vì lật từng trang để biết trang tiếp theo.
Hình 12 · File Allocation Table chainBảng FAT: ô 217 → 618 → 339 → EOF; ô có giá trị 0 là block trống.

5Indexed Allocation: mỗi file 1 index block

In indexed allocation each file has its own index block(s) of pointers to its data blocks. It supports random access and dynamic access without external fragmentation, but costs the overhead of the index block.

Ở cấp phát chỉ mục, mỗi file có index block riêng chứa các con trỏ tới block dữ liệu. Hỗ trợ truy cập ngẫu nhiên và truy cập động không phân mảnh ngoài, nhưng tốn overhead của index block.
📖
Ví dụ đời thườngGiống mục lục ở đầu giáo trình: muốn chương 5, lật mục lục thấy "trang 87" rồi mở thẳng — không cần đọc các chương trước.
Hình 13 · Indexed allocationIndex block giữ danh sách con trỏ tới block dữ liệu rải rác; mục i trỏ tới block thứ i của file.

Example: maximum file size 256 KB, block size 512 bytes ⇒ only 1 index block is needed (512 pointers). Mapping: Q = LA / 512 (displacement into the index table), R = LA mod 512 (displacement into the data block).

Ví dụ: file tối đa 256 KB, block 512 byte ⇒ chỉ cần 1 index block (512 con trỏ). Ánh xạ: Q = LA / 512 (độ dời trong bảng index), R = LA mod 512 (độ dời trong block dữ liệu).
🧮
Ví dụ đời thường256 KB / 512 B = 512 block ⇒ cần 512 con trỏ. Mỗi con trỏ giả sử 1 từ — 1 block 512 ô là vừa đủ chứa cả bảng.

6Index cho file lớn: linked, two-level, combined

When one index block is too small, use a linked scheme: link several index blocks together (no size limit).

Khi 1 index block quá nhỏ, dùng linked scheme: nối nhiều index block với nhau (không giới hạn kích thước).

Mapping: Q1 = LA / (512 × 511) picks the index block; the remainder splits again into Q2 (entry in that index block) and R2 (offset in the data block).

Ánh xạ: Q1 = LA / (512 × 511) chọn index block; phần dư lại tách thành Q2 (mục trong index block đó) và R2 (độ dời trong block dữ liệu).
🧲
Ví dụ đời thườngGiống bộ sách nhiều tập: mỗi tập có mục lục riêng, và cuối mục lục tập này chỉ sang mục lục tập sau.

A two-level index: an outer index points to index blocks, which point to data blocks. With 4 KB blocks and 4-byte pointers: 1,024 × 1,024 = 1,048,576 data blocks ⇒ files up to 4 GB. Mapping: Q1 = LA / (block size × pointers per index block) = LA / (4 KB × 1,024) = LA / 4 MB here. (The lecture's formula LA / (512 × 512) uses a 512-word block as its illustrative example.)

Two-level index: index ngoài trỏ tới các index block, các index block trỏ tới block dữ liệu. Với block 4 KB và con trỏ 4 byte: 1.024 × 1.024 = 1.048.576 block dữ liệu ⇒ file tới 4 GB. Ánh xạ: Q1 = LA / (kích thước block × số con trỏ mỗi index block) = LA / (4 KB × 1.024) = LA / 4 MB ở đây. (Công thức LA / (512 × 512) trong bài giảng dùng ví dụ block 512 từ để minh họa.)
🏬
Ví dụ đời thườngGiống trung tâm thương mại: bảng chỉ dẫn tổng (tầng) → bảng chỉ dẫn từng tầng (gian hàng) → cửa hàng cụ thể. 2 bước tra là tới nơi.
Hình 14 · Two-level indexOuter index → 1.024 index block → mỗi index block → 1.024 block dữ liệu = 1.048.576 block × 4 KB = 4 GB.

The combined scheme (UNIX UFS / inode): 12 direct pointers, plus one single-indirect, one double-indirect and one triple-indirect block pointer. Small files use only direct pointers (fast); huge files use deeper levels.

Combined scheme (UNIX UFS / inode): 12 con trỏ trực tiếp (direct), cộng 1 single-indirect, 1 double-indirect và 1 triple-indirect. File nhỏ chỉ dùng direct (nhanh); file khổng lồ dùng các tầng sâu hơn.
🎒
Ví dụ đời thườngGiống balo có ngăn nhỏ ở mặt trước cho đồ hay dùng (direct) và những ngăn lớn lồng nhau phía sau cho đồ nhiều (indirect).
Hình 15 · UNIX inode: direct + indirect pointersBlock 4 KB, con trỏ 4 byte: 12 direct (48 KB) + single (4 MB) + double (4 GB) + triple (4 TB).

Largest file (4 KB blocks, 4-byte pointers): 12 × 4 KB + 1,024 × 4 KB + 1,024² × 4 KB + 1,024³ × 4 KB = 48 KB + 4 MB + 4 GB + 4 TB ≈ 4 TB.

File lớn nhất (block 4 KB, con trỏ 4 byte): 12 × 4 KB + 1.024 × 4 KB + 1.024² × 4 KB + 1.024³ × 4 KB = 48 KB + 4 MB + 4 GB + 4 TB ≈ 4 TB.

The triple-indirect level dominates: theoretically ≈ 4 TB. But if the file pointer is only 32 bits (max 4 GB), most index blocks — especially the triple-indirect level — cannot be addressed, so large systems use 64-bit pointers.

Tầng triple-indirect chiếm gần hết: về lý thuyết ≈ 4 TB. Nhưng nếu con trỏ vị trí trong file chỉ 32 bit (tối đa 4 GB) thì phần lớn các index block — đặc biệt tầng triple-indirect — không thể được địa chỉ hóa, nên các hệ thống lớn dùng con trỏ 64 bit.
🧾
Ví dụ đời thườngCộng lần lượt như cộng hóa đơn: mỗi tầng gấp 1.024 lần tầng trước, nên cuối cùng tầng sâu nhất to hơn tất cả các tầng còn lại cộng lại.

7Performance: chọn phương pháp nào?

The best method depends on the access type: contiguous is great for sequential and random; linked is good for sequential, not random; indexed is more complex — one block access may need 2 index-block reads then the data block.

Phương pháp tốt nhất tùy kiểu truy cập: contiguous tốt cho cả tuần tự lẫn ngẫu nhiên; linked tốt cho tuần tự, kém cho ngẫu nhiên; indexed phức tạp hơn — truy cập 1 block có thể cần đọc 2 index block rồi mới tới block dữ liệu.

🚗
Ví dụ đời thườngGiống chọn tuyến đường: đường thẳng (contiguous) nhanh nhất nhưng phải có sẵn đoạn trống; đi theo biển báo (linked) thì lâu; có bản đồ (indexed) đi đâu cũng tới nhưng phải mang theo bản đồ.

A file system may declare the access type at creation to choose contiguous or linked. Clustering can improve throughput and reduce CPU overhead.

Hệ thống file có thể khai báo kiểu truy cập lúc tạo để chọn contiguous hoặc linked. Clustering có thể tăng throughput và giảm tải CPU.

For NVM there is no disk head, so different algorithms are needed: old algorithms burn many CPU cycles avoiding non-existent head movement. The goal becomes reducing CPU cycles and the overall I/O path.

Với NVM thì không có đầu đọc đĩa, nên cần thuật toán khác: thuật toán cũ tốn nhiều chu kỳ CPU để tránh việc di chuyển đầu đọc không tồn tại. Mục tiêu chuyển sang giảm chu kỳ CPU và đường đi I/O.
⚡
Ví dụ đời thườngGiống thang máy thay cầu thang: cầu thang cần tính toán đi bậc nào cho đỡ mệt (head), thang máy không cần — thế là ta bỏ luôn các mẹo cũ.

Adding instructions to save one disk I/O is reasonable: a 3.46 GHz CPU at 159,000 MIPS ÷ 250 I/Os per second (HDD) ≈ 630 million instructions per I/O; a fast SSD at 60,000 IOPS gives ≈ 2.65 million.

Thêm lệnh để tiết kiệm 1 lần I/O đĩa là hợp lý: CPU 3,46 GHz ở 159.000 MIPS ÷ 250 I/O/giây (HDD) ≈ 630 triệu lệnh mỗi lần I/O; SSD nhanh 60.000 IOPS cho ≈ 2,65 triệu.
🐢
Ví dụ đời thườngGiống lúc chờ xe buýt 30 phút: trong thời gian đó bạn có thể sắp xếp xong cả balo — CPU cũng vậy, chờ 1 lần đọc đĩa đủ để làm hàng triệu phép tính.

05 · Quản lý chỗ trống

Free-space management: which blocks are still available?

Quản lý chỗ trống: những block nào còn dùng được?

The file system keeps a free-space list to track available blocks/clusters. (We say "block" for simplicity.) Methods: bit vector, linked list, grouping, counting, space maps.

Hệ thống file giữ 1 free-space list để theo dõi block/cluster còn trống. (Gọi "block" cho đơn giản.) Các phương pháp: bit vector, linked list, grouping, counting, space map.

1Bit Vector (Bit Map): mỗi block 1 bit

A bit vector has 1 bit per block: bit[i] = 1 means block i is free, 0 means occupied.

Bit vector có 1 bit cho mỗi block: bit[i] = 1 nghĩa là block i trống, 0 là đã dùng.
🗳️
Ví dụ đời thườngGiống bảng đèn báo ghế ở rạp: ghế nào trống thì đèn xanh (1), có người ngồi thì đèn tắt (0). Nhìn bảng là biết ngay.
Hình 16 · Bit vector for 32 blocksXanh = trống: các block 2–5, 8–13, 17–18, 25–27; máy chỉ cần đọc dãy bit để tìm block trống.

To find the first free block: (bits per word) × (number of 0-valued words) + offset of the first 1 bit. CPUs have instructions that return the offset of the first 1 bit in a word.

Tìm block trống đầu tiên: (số bit mỗi word) × (số word toàn 0) + vị trí bit 1 đầu tiên. CPU có lệnh trả về vị trí bit 1 đầu tiên trong 1 word.
🔦
Ví dụ đời thườngGiống dò hàng ghế: bỏ qua cả hàng toàn ghế kín (word = 0), tới hàng đầu tiên có ghế trống thì đếm ghế nào trống — nhanh nhờ lệnh phần cứng.

The bit map needs extra space. Example: block size 4 KB = 212, disk 240 bytes (1 TB) ⇒ n = 240 / 212 = 228 bits = 32 MB. With clusters of 4 blocks ⇒ 8 MB.

Bit map cần thêm chỗ. Ví dụ: block 4 KB = 212, đĩa 240 byte (1 TB) ⇒ n = 240 / 212 = 228 bit = 32 MB. Nếu dùng cluster 4 block ⇒ 8 MB.
🪄
Ví dụ đời thườngGiống sổ theo dõi từng căn hộ trong tòa 268 triệu căn: mỗi căn chỉ 1 ô tick, nhưng tổng cuốn sổ vẫn nặng 32 MB — nên người ta gộp 4 căn làm 1 ô (cluster) cho gọn còn 8 MB.

Advantage: it is easy to find contiguous files (look for a run of 1s).

Ưu điểm: dễ tìm vùng liên tục cho file (tìm 1 dãy bit 1 liền nhau).

2Linked Free-Space List: nối các block trống

A linked list (free list) chains the free blocks: each free block points to the next. No wasted space, since the pointer lives inside the free block.

1 linked list (free list) nối các block trống: mỗi block trống trỏ tới block trống kế. Không phí chỗ, vì con trỏ nằm ngay trong block trống.

There is no need to traverse the whole list if the number of free blocks is recorded. But you cannot get contiguous space easily.

Không cần duyệt hết nếu có lưu số block trống. Nhưng khó lấy được vùng liên tục.
🎫
Ví dụ đời thườngGiống xếp hàng các vé còn lại: người bán chỉ cần lấy vé đầu hàng, không cần đếm; nhưng muốn 5 vé cạnh nhau thì bất tiện.
Hình 17 · Linked free-space listHead trỏ tới block trống đầu tiên; mỗi block trống trỏ tiếp block trống kế tiếp.

3Grouping và Counting: tối ưu danh sách

Grouping modifies the linked list: the first free block stores the addresses of the next n free blocks, plus a pointer to the next block that holds free-block pointers.

Grouping cải tiến linked list: block trống đầu tiên lưu địa chỉ của n block trống kế tiếp, cộng 1 con trỏ tới block kế tiếp lại chứa các con trỏ free-block.
🚌
Ví dụ đời thườngGiống xe buýt chở 3 khách mỗi chuyến: thay vì mỗi khách đi 1 chuyến riêng, tài xế chở nguyên nhóm 3 người rồi nói điểm đón nhóm sau.
Hình 18 · Grouping with n = 3Block 2 lưu 3, 4, 5; block 5 lưu 8, 9, 10; block 10 lưu 11, 12, 13; block 13 lưu 17, 18, 25; block 25 lưu 26, 27.

Counting: space is often used and freed in contiguous runs (contiguous allocation, extents, clustering), so keep the address of the first free block and the count of the following free blocks.

Counting: chỗ thường được dùng và giải phóng theo từng dải liên tục (contiguous, extent, cluster), nên chỉ cần lưu địa chỉ block trống đầu và số block trống liền sau.
📅
Ví dụ đời thườngGiống ghi lịch nghỉ: thay vì liệt kê "ngày 8, 9, 10, 11, 12, 13", chỉ ghi "từ ngày 8, nghỉ 6 ngày" — gọn hơn nhiều.
Hình 19 · Counting: (start, count) entriesDanh sách (2, 4), (8, 6), (17, 2), (25, 3) mô tả đúng 15 block trống ở hình bit map phía trên.

4Space Maps (ZFS): khi bit map quá lớn

On very large file systems, full structures like bit maps cannot fit in memory — loading them means thousands of I/Os. ZFS uses space maps.

Với hệ thống file rất lớn, các cấu trúc đầy đủ như bit map không nhét vừa bộ nhớ — nạp chúng cần hàng nghìn I/O. ZFS dùng space map.
🏙️
Ví dụ đời thườngGiống bản đồ cả thành phố khổ khổng lồ không thể trải lên bàn: thay vì thế, mỗi quận có 1 tờ riêng, chỉ mở tờ quận cần dùng.

ZFS divides the device into metaslabs (hundreds per volume). Each metaslab has a space map using the counting algorithm, but it records into a log — all block activity in time order.

ZFS chia thiết bị thành các metaslab (hàng trăm mỗi volume). Mỗi metaslab có 1 space map dùng thuật toán counting, nhưng ghi vào 1 log — mọi hoạt động block theo thứ tự thời gian.

When a metaslab is active, its space map is loaded into memory as a balanced tree indexed by offset; the log is replayed into it and adjacent free blocks are combined into one entry.

Khi 1 metaslab hoạt động, space map của nó được nạp vào bộ nhớ dạng cây cân bằng đánh chỉ số theo offset; log được replay vào cây đó và các block trống liền nhau được gộp thành 1 mục.
📓
Ví dụ đời thườngGiống sổ nhật ký thu chi: không sửa số dư liên tục, chỉ ghi từng giao dịch; khi cần tính thì đọc lại nhật ký và gộp lại.
Hình 20 · ZFS space map flowMetaslab → log hoạt động block (counting) → replay vào cây cân bằng trong RAM, gộp block trống liền kề.

5TRIM: báo cho SSD biết block nào đã trống

HDDs overwrite in place, so only a free list is needed: a freed block keeps its data until overwritten.

HDD ghi đè tại chỗ nên chỉ cần free list: block đã giải phóng vẫn giữ dữ liệu cho tới khi bị ghi đè.

Devices that cannot overwrite (e.g. NVM) must erase before writing, erase in large chunks, and erase is slow — so the same algorithm performs badly.

Thiết bị không ghi đè được (ví dụ NVM) phải xóa (erase) trước khi ghi, xóa theo khối lớn và chậm — nên thuật toán cũ chạy rất kém.
🧽
Ví dụ đời thườngHDD giống bảng trắng: viết đè lên cũ là xong. NVM giống bảng đen dùng phấn chỉ được lau cả mảng lớn: muốn viết chỗ nào phải lau trước, lau chậm và tốn công.

TRIM lets the file system tell the NVM device that a page is free, so it can be garbage-collected or, if the whole block is free, the block can be erased in advance.

TRIM cho phép hệ thống file báo với thiết bị NVM rằng 1 page đã trống, nhờ đó có thể garbage-collect hoặc nếu cả block trống thì xóa trước.
🧹
Ví dụ đời thườngGiống nhân viên dọn phòng được báo "phòng 305 vừa trả": dọn sẵn trước, khi khách mới tới chỉ việc vào ở — không phải chờ dọn.

06 · Hiệu quả & hiệu năng

Efficiency and performance: making the file system fast

Hiệu quả và hiệu năng: làm cho hệ thống file chạy nhanh

Disk is the slowest part of a computer. Good file-system design keeps data close together and keeps frequently used blocks in RAM.

Đĩa là phần chậm nhất của máy tính. Thiết kế hệ thống file tốt giữ dữ liệu gần nhau và giữ các block hay dùng trong RAM.

1Efficiency: phụ thuộc vào những gì?

Efficiency depends on the disk allocation and directory algorithms and the types of data kept in a file's directory entry.

Hiệu quả phụ thuộc vào thuật toán cấp phát đĩa và thư mục và loại dữ liệu lưu trong mục thư mục của file.

It also depends on whether metadata structures are pre-allocated or allocated as needed, and whether data structures are fixed-size or varying-size.

Nó còn phụ thuộc metadata được cấp sẵn (pre-allocate) hay cấp khi cần, và cấu trúc dữ liệu có kích thước cố định hay thay đổi.
🏗️
Ví dụ đời thườngGiống xây nhà trọ: xây sẵn 100 phòng (pre-allocate) thì tiện nhưng tốn đất; xây dần theo khách (as-needed) thì tiết kiệm nhưng mỗi lần thêm phải chờ thợ.

2Performance: giữ dữ liệu gần nhau, cache nhiều

Keep data and metadata close together on disk — shorter head movement. Use a buffer cache: a separate part of main memory holding frequently used blocks.

Giữ dữ liệu và metadata gần nhau trên đĩa — đầu đọc di chuyển ít hơn. Dùng buffer cache: 1 vùng riêng của bộ nhớ chính để giữ các block hay dùng.
🍳
Ví dụ đời thườngGiống bếp đặt gia vị ngay cạnh bếp và để đồ hay dùng trên bàn thay vì chạy xuống kho mỗi lần nấu.
Hình 22 · Buffer cache hit and missCache hit: trả lời ngay từ RAM. Cache miss: đọc đĩa rồi giữ lại để lần sau hit.

Synchronous writes (requested by apps or needed by the OS): no buffering — the write must hit the disk before acknowledgement. Asynchronous writes are buffered and faster, and are more common.

Synchronous write (do ứng dụng yêu cầu hoặc OS cần): không buffer — ghi phải xuống đĩa rồi mới trả lời. Asynchronous write được buffer và nhanh hơn, phổ biến hơn.
✉️
Ví dụ đời thườngĐồng bộ giống gửi thư bảo đảm: phải có chữ ký người nhận mới xong. Bất đồng bộ giống thả thư vào hòm: bỏ vào là đi, khỏi chờ.
Hình 23 · Synchronous vs asynchronous writeSync: chờ đĩa xác nhận. Async: ghi vào buffer là trả lời, đĩa ghi sau.

Free-behind and read-ahead optimize sequential access: read-ahead prefetches the next blocks, free-behind drops blocks already used. Also, reads are frequently slower than writes (a write can be buffered; a read must wait for data).

Free-behind và read-ahead tối ưu truy cập tuần tự: read-ahead đọc trước các block kế, free-behind bỏ các block đã dùng. Ngoài ra, read thường chậm hơn write (write có thể buffer; read phải chờ dữ liệu).
📺
Ví dụ đời thườngGiống xem YouTube: app tải trước vài giây phía sau (read-ahead) và bỏ phần đã xem khỏi bộ nhớ (free-behind) để video chạy mượt.
Hình 24 · Read-ahead and free-behindĐọc tuần tự: tải trước các block phía sau, giải phóng các block phía trước đã dùng xong.

3Page Cache và Unified Buffer Cache

A page cache caches pages (not disk blocks) using virtual-memory techniques and addresses. Memory-mapped I/O uses a page cache, while routine file-system I/O uses the buffer (disk) cache.

Page cache cache các page (không phải block đĩa) bằng kỹ thuật và địa chỉ bộ nhớ ảo. Memory-mapped I/O dùng page cache, còn I/O file thông thường dùng buffer (disk) cache.
🗂️
Ví dụ đời thườngGiống 2 tủ hồ sơ khác nhau trong cùng 1 công ty: phòng A (memory-mapped) giữ bản photo theo trang, phòng B (read/write) giữ bản theo từng tập.
Hình 25 · I/O without a unified buffer cacheCó 2 cache riêng ⇒ cùng 1 dữ liệu có thể bị cache 2 lần (double caching).

A unified buffer cache uses the same page cache for both memory-mapped pages and ordinary file-system I/O, avoiding double caching. Open questions: which caches get priority, and which replacement algorithms to use?

Unified buffer cache dùng cùng 1 page cache cho cả page memory-mapped lẫn I/O file thường, tránh double caching. Câu hỏi còn lại: cache nào được ưu tiên, và dùng thuật toán thay thế nào?
🎯
Ví dụ đời thườngGiống hợp 2 kệ sách trùng nhau thành 1 kệ chung: cuốn nào cũng chỉ có 1 bản, đỡ tốn chỗ và không lẫn phiên bản.
Hình 26 · I/O using a unified buffer cache1 cache chung phục vụ cả 2 kiểu I/O: không còn lưu trùng.

07 · Phục hồi & ví dụ thực tế

Recovery, journaling, and real-world file systems (WAFL, APFS)

Phục hồi, journaling và các hệ thống file thực tế (WAFL, APFS)

Files and directories live both in memory and on disk. If the system crashes, metadata can become inconsistent. This tab covers how file systems recover and how real systems optimize.

File và thư mục nằm cả trong bộ nhớ lẫn trên đĩa. Nếu hệ thống sập, metadata có thể bị lệch. Tab này nói về cách hệ thống file phục hồi và cách các hệ thống thực tế tối ưu.

1Recovery: kiểm tra nhất quán và sao lưu

Consistency checking compares the data in the directory structure with the data blocks on disk, and tries to fix inconsistencies. It can be slow and sometimes fails.

Consistency checking so sánh dữ liệu trong cấu trúc thư mục với các block dữ liệu trên đĩa, và cố sửa các chỗ lệch. Việc này có thể chậm và đôi khi thất bại.
🧯
Ví dụ đời thườngGiống kế toán đối chiếu sổ cái với hóa đơn cuối tháng: lệch số nào thì dò tìm và sửa — chính xác nhưng mất thời gian khi sổ dày.
Hình 27 · Consistency checkingSo thư mục với block thật trên đĩa; chỗ nào lệch thì tìm cách sửa (có thể chậm, có thể thất bại).

Use system programs to back up data from disk to another device (magnetic tape, other magnetic disk, optical). Recover a lost file or disk by restoring data from backup.

Dùng chương trình hệ thống để sao lưu (backup) dữ liệu từ đĩa sang thiết bị khác (băng từ, đĩa từ khác, đĩa quang). Phục hồi file hoặc đĩa bị mất bằng cách khôi phục dữ liệu từ bản backup.
📸
Ví dụ đời thườngGiống chụp ảnh giấy tờ quan trọng gửi email cho mình: làm rơi ví mất bản gốc vẫn còn bản sao để làm lại.

2Log-Structured (Journaling) File Systems

Log-structured (or journaling) file systems record each metadata update as a transaction, and write all transactions to a log.

Hệ thống file log-structured (hay journaling) ghi mỗi lần cập nhật metadata thành 1 transaction, và ghi mọi transaction vào 1 log.

A transaction is committed once it is written to the log (sequentially), even though the file system itself may not yet be updated.

1 transaction được coi là committed ngay khi đã ghi vào log (tuần tự), dù file system thật có thể chưa được cập nhật.
🪣
Ví dụ đời thườngGiống kế toán ghi nhanh vào sổ nhật ký trước ("đã nhận 5 triệu"), rồi mới rảnh thì chép sang sổ cái. Nhật ký có rồi là coi như xong việc.

The logged transactions are asynchronously applied to the file-system structures. When the structures are modified, the transaction is removed from the log.

Các transaction trong log được áp dụng bất đồng bộ vào cấu trúc file system. Khi các cấu trúc đã được sửa, transaction bị xóa khỏi log.

If the system crashes, all remaining transactions in the log must still be performed. Result: faster recovery and no chance of metadata inconsistency.

Nếu hệ thống sập, mọi transaction còn lại trong log vẫn phải được thực hiện. Kết quả: phục hồi nhanh hơn và không còn khả năng metadata lệch nhau.
🧵
Ví dụ đời thườngGiống đang chép bài thì mất điện: mở máy lại, đọc nhật ký "đang chép đến dòng 40" rồi chép tiếp — khỏi đọc lại cả vở từ đầu.
Hình 28 · Journaling flowGhi log trước (commit) → áp dụng vào FS thật → xóa log. Sập giữa chừng thì replay log.

3Example: WAFL File System

WAFL (Write-Anywhere File Layout) is used on Network Appliance "Filers" — distributed file-system appliances that serve NFS, CIFS, HTTP, FTP.

WAFL (Write-Anywhere File Layout) dùng trên các "Filer" của Network Appliance — thiết bị hệ thống file phân tán phục vụ NFS, CIFS, HTTP, FTP.
🏪
Ví dụ đời thườngGiống 1 cửa hàng tiện lợi nhiều quầy: 1 hệ thống bên trong nhưng phục vụ khách bằng nhiều cách (NFS, CIFS, web…).

WAFL is random-I/O optimized and write optimized, using NVRAM for write caching. It is similar to the Berkeley Fast File System, with extensive modifications.

WAFL được tối ưu cho I/O ngẫu nhiên và ghi, dùng NVRAM làm cache ghi. Tương tự Fast File System của Berkeley, với nhiều sửa đổi lớn.
📝
Ví dụ đời thườngGiống nhân viên ghi nhanh vào giấy nhớ (NVRAM — không mất khi tắt điện), sau đó mới chép vào hồ sơ chính khi rảnh.

Its snapshots are cheap: a snapshot copies the root, and blocks are shared with the active file system.

Snapshot của nó rất rẻ: snapshot chỉ chép root, còn block được chia sẻ với file system đang chạy.

Modified blocks are written to new locations (write-anywhere), so old blocks stay available to the snapshot.

Block bị sửa được ghi vào chỗ mới (write-anywhere), nên block cũ vẫn dành cho snapshot.
📷
Ví dụ đời thườngGiống chụp ảnh 1 bàn làm việc: chụp xong cứ tiếp tục làm việc; chỗ nào bạn thay đổi thì đặt đồ mới ra bàn, còn ảnh vẫn giữ nguyên hiện trạng cũ.
Hình 29 · WAFL snapshotSnapshot dùng chung block với FS đang chạy; khi sửa B thì ghi B′ ở chỗ mới, B cũ vẫn thuộc về snapshot.

4The Apple File System (APFS)

The lecture gives only the title and a figure for the Apple File System. In short, APFS is the modern file system of Apple devices.

Bài giảng chỉ có tiêu đề và 1 hình cho Apple File System. Nói ngắn gọn, APFS là hệ thống file hiện đại của thiết bị Apple.

It follows trends seen in this chapter: copy-on-write metadata, snapshots, space sharing between volumes, and SSD/NVM-friendly design.

Nó theo các xu hướng đã thấy trong chương: metadata copy-on-write, snapshot, chia sẻ không gian giữa các volume, và thiết kế phù hợp SSD/NVM.
🍎
Ví dụ đời thườngGiống 1 tòa nhà thông minh đời mới: vẫn là nhà (file system), nhưng được thiết kế lại cho thiết bị mới (SSD) và có sẵn tính năng chụp ảnh hiện trạng (snapshot).

Bài 1 — Ánh xạ logical → physical trong contiguous allocation

A file is allocated contiguously starting at block 100. Block size is 512 bytes. Which physical block and which displacement correspond to logical address LA = 1300?

1 file được cấp phát liên tục bắt đầu tại block 100. Kích thước block là 512 byte. Địa chỉ logic LA = 1300 ứng với block vật lý nào và độ dời bao nhiêu?
Xem đáp án

Q = LA / 512 = 1300 / 512 = 2 (phần nguyên), R = 1300 mod 512 = 1300 − 1024 = 276.

Block cần truy cập = Q + starting address = 2 + 100 = block 102, độ dời trong block = 276.

Bài 2 — Ánh xạ trong linked allocation

Each block is 512 bytes: 1 byte pointer area is reserved so that 511 bytes hold data (as in the lecture mapping, where the unit is a word: 512 words per block, 1 word is the pointer). For LA = 1300, find Q, R, and the displacement into the block.

Mỗi block 512 byte, trong đó dành chỗ cho con trỏ nên 511 byte chứa dữ liệu (theo ánh xạ trong bài giảng, đơn vị là từ/word: 512 từ mỗi block, 1 từ là con trỏ). Với LA = 1300, tìm Q, R và độ dời trong block.
Xem đáp án

Q = 1300 / 511 = 2 (vì 2 × 511 = 1022 ≤ 1300 < 1533), R = 1300 − 1022 = 278.

Phải đi theo chuỗi tới block thứ Q = 2 (tính block đầu là số 0) — tức qua 2 con trỏ — rồi đọc tại độ dời R + 1 = 279 (cộng 1 để bỏ qua ô con trỏ).

Nhận xét: truy cập ngẫu nhiên phải duyệt chuỗi, nên linked allocation kém ở random access.

Bài 3 — Kích thước file tối đa của inode UNIX

An inode has 12 direct, 1 single-indirect, 1 double-indirect and 1 triple-indirect pointer. Block size is 1 KB and a pointer is 4 bytes. What is the largest file?

1 inode có 12 con trỏ direct, 1 single-indirect, 1 double-indirect và 1 triple-indirect. Block 1 KB, con trỏ 4 byte. File lớn nhất là bao nhiêu?
Xem đáp án

Mỗi block chứa 1024 / 4 = 256 con trỏ.

Direct: 12 × 1 KB = 12 KB. Single: 256 × 1 KB = 256 KB. Double: 256² × 1 KB = 65.536 KB = 64 MB. Triple: 256³ × 1 KB = 16.777.216 KB = 16 GB.

Tổng ≈ 16 GB + 64 MB + 256 KB + 12 KB ≈ 16 GB (tầng triple chiếm gần hết). Với block 4 KB và con trỏ 4 byte (bài giảng): ≈ 4 TB.

Bài 4 — Kích thước bit map

A disk has 2 TB (241 bytes) and the block size is 4 KB (212). How large is the free-space bit map? How large if blocks are grouped into clusters of 8?

Đĩa 2 TB (241 byte), block 4 KB (212). Bit map chỗ trống lớn bao nhiêu? Nếu gom thành cluster 8 block thì bao nhiêu?
Xem đáp án

Số block n = 241 / 212 = 229 block ⇒ 229 bit = 226 byte = 64 MB.

Cluster 8 block: 229 / 8 = 226 bit = 223 byte = 8 MB.

(Cùng cách tính với ví dụ 1 TB → 32 MB → 8 MB trong bài giảng.)

Bài 5 — Grouping và counting

Free blocks are: 3, 4, 5, 6, 10, 11, 20, 21, 22. Write the counting representation, and the grouping (n = 3) chain starting from block 3.

Các block trống: 3, 4, 5, 6, 10, 11, 20, 21, 22. Viết dạng counting, và chuỗi grouping (n = 3) bắt đầu từ block 3.
Xem đáp án

Counting (start, count): (3, 4), (10, 2), (20, 3).

Grouping n = 3: block 3 lưu 4, 5, 6; block 6 lưu 10, 11, 20; block 20 lưu 21, 22.

Nhận xét: counting rất gọn khi block trống nằm thành dải dài; grouping vẫn cần nhiều block khi trống rời rạc.

Bài 6 — Vì sao journaling phục hồi nhanh hơn fsck?

Explain why a journaling file system recovers faster than a full consistency check after a crash.

Giải thích vì sao hệ thống file journaling phục hồi nhanh hơn việc chạy kiểm tra nhất quán toàn bộ sau khi sập.
Xem đáp án

Consistency check phải so sánh toàn bộ cấu trúc thư mục với các block trên đĩa — chậm, tỉ lệ theo kích thước đĩa, và đôi khi thất bại.
